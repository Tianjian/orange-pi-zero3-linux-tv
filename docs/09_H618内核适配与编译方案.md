# 09 · H618 / Orange Pi Zero 3 的 Linux 内核适配与编译方案

> 目标：基于官方 `orangepi-build` 的内核源码、配置与工具链，给出 **H618（Orange Pi Zero 3）板载外设的
> Linux 内核配置、设备树使能、工具链与编译/验证方案**，并说明什么时候该走厂商树、什么时候可以走主线。
>
> 依据：
> - 用户手册 v1.6、原理图 Rev1.2（本仓库 `docs/01`–`docs/03`）
> - Allwinner **H616** 产品简介（`docs/source/h616-soc.pdf`，H618 无公开 datasheet，H616 作为同 die 参考）
> - `orangepi-build@next`（commit `a95129b`）与 `linux-orangepi@orange-pi-6.1-sun50iw9`（commit `7114452`）
> - 主线与社区调研：[docs/08_社区与主线调研.md](08_社区与主线调研.md)
> - 机制与逐项配置审计：[docs/07_orangepi-build内核机制与配置分析.md](07_orangepi-build内核机制与配置分析.md)
> - 实测构建结果：[docs/10_内核构建验证.md](10_内核构建验证.md)

## 0. 结论速览

| # | 结论 | 依据 |
|---|---|---|
| 1 | **官方 6.1 = 主线 6.1.31 + 大量全志 BSP 增量**（单条 squash 导入），不是纯主线；显示用主线 DRM，音频/无线/VPU 用厂商驱动 | `kernel/src/linux-6.1` 树内 `sound/soc/sunxi_v2/`、`drivers/net/wireless/uwe5622/`、`drivers/staging/media/sunxi/cedrus`（H616 variant） |

| 3 | **Wi-Fi/BT 必须用厂商树**：驱动在 6.1 树内（`uwe5622_bsp_sdio`/`sprdwl_ng`/`sprdbt_tty`），主线完全没有该驱动，也无排队补丁 | 树内源码 + `docs/08` §3 |
| 4 | **主线“能跑”≠“能用”**：DTS 从 v6.6 进主线，但到 v7.4 仍无 HDMI/DE 节点；codec 6.15、GPU 7.0、VPU 7.4 才落地 | `docs/08` §2 |
| 5 | **H618 = H616 同 die 修订**（新 cluster 控制子系统 + L2 512KB→1MB），SoC 级 dtsi 完全复用 `sun50i-h616.dtsi` | `docs/08` §1 |
| 6 | 千兆网口用主线 `stmmac + YT8531C`，但 **RGMII 三个参数**（`rgmii-rxid`/`tx-delay-ps=700`/`clk-out 125MHz`）缺一不可 | `docs/08` §4.1 |
| 7 | 工具链用官方同款 **Arm GNU 11.2-2022.02 aarch64-none-linux-gnu**；已验证可编出 Image/modules/dtb/内核模块 | [docs/10](10_内核构建验证.md) |
| 8 | 编译入口：`scripts/build_kernel.sh`（一条命令）；验证入口：`scripts/verify_kernel_build.sh` | 本仓库脚本 |
| 9 | 官方 .config 很大（1966 个 `=y` + 2909 个 `=m`），含大量他板驱动；产品化建议裁剪 | `kernel/out/6.1/.config` |
| 11 | **VPU**：厂商 6.1 里 `CONFIG_VIDEO_SUNXI_CEDRUS=m`，dtsi 的 `video-codec@1c0e000` 默认启用（H616 variant 复用 H6 表），但用户态需 v4l2-request；手册“Linux 视频解码 NO”应理解为官方镜像未交付可用栈，需实测 | `.config`、`sun50i-h616.dtsi:193`、`cedrus.c:652/707` |
| 10 | 改内核源码前必须 `IGNORE_UPDATES="yes"`，否则 SDK 同步会覆盖 | `docs/04`、SDK 脚本 |

## 1. 目标板外设 → 内核映射

| 外设（板载/排针） | 硬件接口 | 内核驱动（厂商 6.1） | 关键配置符号 | 设备树节点 | 默认状态 |
|---|---|---|---|---|---|
| CPU 4×A53 / DVFS | — | `cpufreq-dt` + `sun50i-cpufreq-nvmem` | `CPUFREQ_DT`、`SUN50I_CPUFREQ_NVMEM` | `cpu0` + `cpu-opp` | okay |
| LPDDR4 | — | 无（U-Boot 初始化） | — | `memory` | — |
| TF 卡 | SDC0 | `mmc-sunxi` | `MMC_SUNXI`、`MMC_BLOCK` | `mmc0`（`cd-gpios=PF6`） | okay |
| SPI NOR 16Mbit | SPI0 | `spi-sun6i` + `spi-nor` | `SPI_SUN6I`、`MTD_SPI_NOR` | `spi0` + `flash@0` | okay |
| 千兆以太网 | GMAC + RGMII | `dwmac-sun8i` + `motorcomm` | `DWMAC_SUN8I`、`MOTORCOMM_PHY` | `emac0` + `mdio0`（PHY addr 1） | okay |
| Wi-Fi/BT | SDIO 4bit + UART/PCM | **厂商** `uwe5622_bsp_sdio`/`sprdwl_ng`/`sprdbt_tty` | `AW_WIFI_DEVICE_UWE5622`、`WLAN_UWE5622`、`SPRDWL_NG`、`TTY_OVERY_SDIO` | `mmc1` + `wifi-pwrseq`（厂商 DTS） | okay（厂商） |
| USB0（Type-C OTG） | USB2.0 OTG | **MUSB**（`sun50i-h616-musb`） | `USB_MUSB_SUNXI`（peripheral） | `usbotg` | okay（peripheral） |

| USB2/USB3（13pin） | EHCI/OHCI | 同上 | 同上 | `ehci2/3`、`ohci2/3` | okay |
| HDMI | HDMI 2.0a | `sun4i-drm` + `dw-hdmi` | `DRM_SUN4I`、`DRM_SUN8I_DW_HDMI`、`DRM_SUN8I_MIXER` | `hdmi` + `de` | okay |
| 模拟音频（13pin） | Codec + AHUB | **厂商** `sun50iw9-codec` + `sunxi_v2` AHUB | `SND_SUN50IW9_CODEC`、`SND_SOC_SUNXI_AHUB`（vendor） | `codec` + `ahub*` | okay |
| IR（13pin） | IR-RX | `sunxi-ir` | `RC_CORE`、`IR_SUNXI` | `ir` | okay |
| 26pin I2C3 | TWI3 | `i2c-mv64xxx` | `I2C_MV64XXX` | `i2c3` | **disabled**（dtbo） |
| 26pin UART5 | UART5 | `8250_dw` | `SERIAL_8250_DW` | `uart5` | **disabled**（dtbo） |
| 26pin SPI1 | SPI1 | `spi-sun6i` + `spidev` | `SPI_SUN6I`、`SPI_SPIDEV` | `spi1` + `spidev@1` | **disabled**（dtbo） |
| 26pin PWM | PWM | `pwm-sun4i` | `PWM_SUN4I` | `pwm`/`pwm1..4` | **disabled**（dtbo） |
| 26pin GPIO | PIO | `gpiolib` + `pinctrl-sunxi` | `GPIOLIB`、`PINCTRL_SUN50I_H616` | `pio` | okay |
| PMIC AXP313A | RSB（r_i2c 0x36） | `axp20x-rsb` + `axp20x-regulator` | `MFD_AXP20X_RSB`、`REGULATOR_AXP20X` | `axp313a` | okay |
| 温度 | THS | `sun8i-thermal` | `SUN8I_THERMAL` | `thermal-zones` | okay |
| 看门狗 | WDT | `sunxi-wdt` | `SUNXI_WATCHDOG` | `watchdog` | okay |
| RTC | RTC | `rtc-sun6i` | `RTC_DRV_SUN6I` | `rtc` | okay |
| 板载 LED | GPIO PC12/PC13 | `leds-gpio` | `LEDS_GPIO` | `leds` | okay |

### 1.1 H616 产品简介（PDF）里的关键规格与内核含义

> H618 无公开 datasheet，官方只给了 **H616 产品简介**（`docs/source/h616-soc.pdf`，2 页，2019-12）。
> H618 与 H616 是同一颗 die 的修订版（L2 512KB→1MB，见 `docs/08` §1），所以这份 brief 是内核适配的主要 SoC 参考。

| PDF 规格 | 具体参数 | 对内核适配的含义 |
|---|---|---|
| CPU | 4×Cortex-A53，64 位 | `ARM64` + `ARCH_SUNXI` + `CPUFREQ_DT`（OPP 在 `sun50i-h616-cpu-opp.dtsi`） |
| GPU | G31 MP2，OpenGL ES 3.2/2.0/1.0、Vulkan 1.1、OpenCL 2.0 | `DRM_PANFROST`；但厂商 Zero3 DTS 把 `gpu` 设为 disabled，需 overlay 才启用 |
| 视频解码 | H.265 Main10 4K60/6K30、VP9 4K60、AVS2 4K60、H.264 4K30 | 主线 `cedrus`（7.4 才支持 H616）；厂商 6.1 有 `VIDEO_SUNXI_CEDRUS=m` + H616 variant |
| 视频编码 | H.264 4K25 / 1080p60 | **无主线驱动**；厂商 6.1 也未启用编码器（不要承诺） |
| 显示 | HDMI 2.0a 4K60、TV CVBS PAL/NTSC、DE3.3 | `DRM_SUN4I`+`DRM_SUN8I_DW_HDMI`+`DRM_SUN8I_MIXER`；TV-OUT 无 Linux 驱动（Android 才有） |
| 音频 | 2ch DAC、Audio HUB（3×I2S/PCM）、DMIC、OWA OUT | 厂商 `SND_SUN50IW9_CODEC` + AHUB；主线 codec 6.15 才有 |
| 内存 | DDR4/DDR3/DDR3L/LPDDR3/LPDDR4，32-bit，最大 4GB；8-bit NAND；SD3.0/eMMC5.0 | 内存由 U-Boot 初始化；`MMC_SUNXI` 覆盖 SD/eMMC/SDIO |
| 以太网 | 1×10/100/1000（RGMII/RMII）+ 1×100M 内置 PHY | Zero3 用外置 **YT8531C**（RGMII，`dwmac-sun8i`+`motorcomm`）；内置 100M EPHY 全部 NC |
| USB | 3×USB2.0 Host + 1×USB2.0 OTG | `EHCI/OHCI platform` ×3 + **MUSB**（`sun50i-h616-musb`；Zero3 的 Type-C OTG 只做 peripheral） |
| 其他 | SDIO 3.0、TSC、CIR、TWI、SPI、UART、PWM、LRADC | 对应 `MMC_SUNXI`、`IR_SUNXI`、`I2C_MV64XXX`、`SPI_SUN6I`、`8250_DW`、`PWM_SUN4I` |
| 封装 | TFBGA-284，14×12mm，0.65mm pitch | 与 Zero3 原理图 `H616-BGA-284` 一致；H618 同封装 |

> 注意：brief 写“6K@30 H.265 解码”，H618 官方文案写“8K@24”，二者冲突（见 `docs/08` §1.3），
> **方案里不要承诺 8K**；以实测/官方 BSP 能力为准。

## 2. 三条内核路线怎么选

| 维度 | 官方 6.1（推荐默认） | 官方 5.4 BSP | 主线 6.18 / 7.0+ |
|---|---|---|---|
| 源码 | `orange-pi-6.1-sun50iw9`（主线 6.1.31 + BSP） | `orange-pi-5.4-sun50iw9`（全志 BSP） | torvalds/linux |
| 显示 | 主线 DRM（HDMI 可用） | 厂商 display2（HDMI 可用） | **HDMI/DE 无节点**（7.4 仍无） |
| 音频 codec | 厂商 `SND_SUN50IW9_CODEC` | 厂商 `SND_SOC_SUNXI_*` | 6.15 起有 codec 节点 |
| Wi-Fi/BT | 树内厂商 uwe5622 | 树内厂商 uwe5622 | **无驱动**（需外挂 DKMS） |
| GPU | Panfrost 模块（可用性未验证） | 厂商 Mali（out-of-tree 模块） | 7.0+ 才可用 |
| VPU 硬解 | `cedrus=m` + H616 variant 节点默认启用，用户态需 v4l2-request（可用性待实测） | 厂商 cedar（out-of-tree） | 7.4 才合入 |
| 维护性 | 中（全志 BSP 混合） | 低（老 BSP） | 高 |
| 适合 | **产品默认、要全外设** | 老项目/厂商补丁依赖 | 上游化、无 HDMI/WiFi 需求 |

**建议**：
- 要“板子所有外设都能用” → **官方 6.1**（本方案主线）。
- 要跟上游/长期维护、且能接受无 HDMI、无板载 WiFi → 主线 6.18+（最好 7.0+）。
- 5.4 只用于必须复刻老 BSP 行为的场景；新项目不建议。

## 3. orangepi-build 的内核构建机制（要点）

> 逐行证据见 [docs/07](07_orangepi-build内核机制与配置分析.md)。这里只给结论。

1. **板级配置** `external/config/boards/orangepizero3.conf`：
   `BOARDFAMILY="sun50iw9"`、`KERNEL_TARGET="current,next"`、`BOOTCONFIG="orangepi_zero3_defconfig"`、
   `MODULES_NEXT="uwe5622_bsp_sdio sprdwl_ng sprdbt_tty"`。
2. **家族配置** `external/config/sources/families/sun50iw9.conf`：
   - `current` → `KERNELBRANCH="branch:orange-pi-5.4-sun50iw9"`、U-Boot `v2018.05-h618`
   - `next` → `KERNELBRANCH="branch:orange-pi-6.1-sun50iw9"`、`LINUXCONFIG="linux-6.1-sun50iw9-next"`、U-Boot `v2024.01` + ATF `sun50i_h616`
3. **工具链**：arm64 用 `aarch64-none-linux-gnu-`，`KERNEL_USE_GCC='> 10.0'`；
   SDK 从清华镜像下载 `gcc-arm-11.2-2022.02-x86_64-aarch64-none-linux-gnu.tar.xz`，
   `find_toolchain()` 在 `toolchains/*/bin` 里选版本最接近的一个。
4. **编译流程**（`scripts/compilation.sh: compile_kernel`）：
   ```
   复制 external/config/kernel/<LINUXCONFIG>.config  ->  .config
     -> custom_kernel_config hook（可注入） 
     -> make olddefconfig（KERNEL_CONFIGURE!=yes）
     -> make -j Image modules dtbs LOCALVERSION=-sun50iw9
     -> bindeb-pkg 打包 linux-image/headers/dtb
   ```
   `KERNEL_IMAGE_TYPE=Image`（arm64；`configuration.sh` 里的 `zImage` 是 armhf 默认，被 `arm64.conf` 覆盖）。
5. **补丁**：`KERNELPATCHDIR=sun50iw9-next`，但 SDK 的 `external/patch/` 下只有 `atf/` 与 `misc/`，
   **没有内核补丁目录**——即 6.1 内核是分支原样编译，BSP 改动已直接提交在分支里。
6. **`LOCALVERSION=-sun50iw9`** 会写进内核版本串与模块 vermagic，自编模块必须一致。
7. **产物**：`output/debs/linux-image-next-sun50iw9_*.deb`、`linux-dtb-*`、`linux-headers-*`；
   模块由 `MODULES_*` 列表装进 rootfs。

## 4. 官方 6.1 配置审计

### 4.1 规模

| 项 | 6.1 next | 5.4 current |
|---|---|---|
| .config 行数 | 8442 | 6457 |
| `=y` | 1966 | 2081 |
| `=m` | 2909 | 847 |
| 结论 | 接近 Debian 通用内核，含大量他板驱动 | 更像板级定制，模块少 |

### 4.2 外设覆盖（`scripts/check_kernel_config.py`）

审计 29 组外设/基础设施，结果：**必选项缺失 0**，风险项 1（`MODULE_SIG_ALL=y`）。
详细表见 [docs/10](10_内核构建验证.md) 与 `kernel/out/audit-6.1.csv`。

### 4.3 厂商私有符号（主线没有，迁移时最容易踩）

| 功能 | 厂商 6.1 符号 | 说明 |
|---|---|---|
| 模拟 codec | `SND_SUN50IW9_CODEC` | `sound/soc/sunxi/sun50iw9-codec.c`，compatible `allwinner,sun50i-h616-codec` |
| AHUB/DAM | `SND_SOC_SUNXI_AHUB`、`SND_SOC_SUNXI_AHUB_DAM` | `sound/soc/sunxi_v2/` |
| 音频 machine | `SND_SOC_SUNXI_MACH` | 同上 |
| Wi-Fi/BT | `AW_WIFI_DEVICE_UWE5622`、`WLAN_UWE5622`、`SPRDWL_NG`、`TTY_OVERY_SDIO` | `drivers/net/wireless/uwe5622/` |
| 厂商网卡残留 | `SUNXI_GMAC=y`、`sunxi-ephy.c` | Zero3 **不会绑定**（DTS 是 `sun50i-h616-emac0` → `dwmac-sun8i=m` + `motorcomm`）；`sunxi-ephy.c` 无 CONFIG 符号、被硬编进 libphy，只注册 ephy/ac300，与 YT8531C 无关 |
| VPU（Cedrus） | `VIDEO_SUNXI_CEDRUS=m` | 厂商 6.1 已带 H616 variant（`cedrus.c:707`），非“未启用”；主线 7.4 才有 |

> 结论：**把 6.1 的 .config 直接搬到主线会丢音频/WiFi**；反过来把主线 config 搬回厂商树会少符号。

## 5. 配置方案

### 5.1 直接复用官方 .config（推荐）

```bash
cp vendor/orangepi-build/external/config/kernel/linux-6.1-sun50iw9-next.config .config
make ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- olddefconfig
```

`olddefconfig` 只会改工具链版本相关项（实测 16 行差异：`CC_VERSION_TEXT`/`GCC_VERSION`/`AS_VERSION`/GCC 插件），
外设配置不变。

### 5.2 从零/裁剪：用片段

`kernel/config/opiz3-h618-6.1-vendor.fragment` 覆盖 Zero3 全部外设，可合并到 `arm64 defconfig`：

```bash
make ARCH=arm64 defconfig
scripts/kconfig/merge_config.sh -m .config kernel/config/opiz3-h618-6.1-vendor.fragment
make ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- olddefconfig
```

### 5.3 裁剪建议（产品化）

官方配置 2909 个模块，含大量无关网卡/文件系统/调试驱动。建议：

```bash
# 在能启动的板子上采集实际加载的模块，再回主机裁剪
lsmod | awk 'NR>1{print $1}' > /tmp/used.txt
# 内核树内：
make ARCH=arm64 LSMOD=/tmp/used.txt localmodconfig
# 再按需打开：USB gadget、spidev、i2c-dev、pwm、ir、audio
```

注意：
- `localmodconfig` 会关掉“当前没加载但产品需要”的驱动，务必对照 §1 清单逐项复核。
- 不要关 `DEVTMPFS`、`BLK_DEV_INITRD`、`EXT4`（rootfs）、`MMC_SUNXI`。
- `MODULE_SIG_ALL=y`：自编 out-of-tree 模块会被签名（无强制校验则能加载）；量产建议关掉或统一签名。

### 5.4 主线片段

`kernel/config/opiz3-h618-mainline.fragment` 面向 upstream v6.6+，只含主线存在的符号；
音频 codec / 无线 / 显示在主线上的缺口见 §2 与 [docs/08](08_社区与主线调研.md)。

## 6. 设备树适配

### 6.1 官方 6.1 DTS 的默认状态

（`sun50i-h618-orangepi-zero3.dts`，本仓库也有摘录 `hardware/dts-ref/`）

| 节点 | status | 说明 |
|---|---|---|
| `mmc0` | okay | TF 卡，`cd-gpios=PF6`（经 Q1 反相） |
| `mmc1` | okay | SDIO WiFi，`non-removable` + `mmc-pwrseq`（**主线没有**） |
| `spi0` + `flash@0` | okay | 16Mbit SPI NOR，40MHz |
| `emac0`/`mdio0` | okay | RGMII，`rx-delay-ps=1800`、`tx-delay-ps=700`、PHY addr 1 |
| `usbotg` | okay | `dr_mode="peripheral"`（Type-C 只供电，不做 host） |
| `ehci/ohci 1..3` | okay | 3 个 host（USB0 的 ehci0/ohci0 disabled） |
| `hdmi`/`de` | okay | 主线 DRM |
| `codec` + `ahub*` | okay | 厂商音频 |
| `ir` | okay | 13pin 红外 |
| `i2c3` / `uart5` / `spi1` | **disabled** | 26pin，靠 dtbo 打开 |
| `i2c1/2/4`、`uart2` | disabled | 未引出/未用 |
| `gpu` | **disabled** | 厂商 DTS 明确关闭 GPU |

### 6.2 26pin 功能使能 = 官方 dtbo（推荐）

| 功能 | dtbo | 生效后节点 |
|---|---|---|
| UART5 | `sun50i-h616-ph-uart5.dtbo` | `/dev/ttyS5`（6.1）/`ttyAS5`（5.4） |
| I2C3 | `sun50i-h616-ph-i2c3.dtbo` | `/dev/i2c-3` |
| SPI1 | `sun50i-h616-spi1-cs1-spidev.dtbo` | `/dev/spidev1.1` |
| PWM1/2 | `sun50i-h616-ph-pwm12.dtbo` | `/sys/class/pwm/pwmchip0/pwm1..2` |
| 关调试串口（给 PWM3/4） | `sun50i-h616-disable-uart0.dtbo` | 控制台消失，慎用 |

在官方镜像里等价操作：`sudo orangepi-config` → System → Hardware 勾选后重启。

### 6.3 自己写 DTS/overlay 时的注意点

- **H618 复用 H616 的 SoC dtsi**：`compatible = "allwinner,sun50i-h618"`，引脚组名（`uart5_ph_pins` 等）与 H616 一致。
- **PH2/PH3** 同时是 UART5 与 PWM1/PWM2；**PH0/PH1** 同时是 UART0 与 PWM3/PWM4。overlay 不能同时开。
- **13pin 的 PI16** 在 `ext_rgmii_pins` 组里（`emac0`），作 GPIO 可能 EBUSY；需要时裁 pinctrl 并复测以太网（`docs/03` D8）。
- **主线 DTS** 可直接抄 `sun50i-h616-orangepi-zero.dtsi`/`sun50i-h618-orangepi-zero3.dts`，
  但必须补：`mmc1`（WiFi）、`codec`/`ahub`（若用厂商树）、以及注意 PMIC 中断 parent 的已知问题（`docs/08` §4.2）。
- 生效验证：
  ```bash
  dmesg | grep -iE "pinctrl|mmc1|emac|codec|hdmi|axp"
  cat /sys/kernel/debug/pinctrl/*/pinmux-pins | grep -E "PH2|PH3|PH4|PH5"
  ```

### 7.1 版本选择

| 组件 | 版本 | 与官方关系 |
|---|---|---|
| 交叉编译器 | **Arm GNU Toolchain 11.2-2022.02**（`aarch64-none-linux-gnu-gcc 11.2.1`） | 官方手册指定 11.2；注意 SDK next 分支 `KERNEL_USE_GCC` 落到 `>8.0`，若 `toolchains/` 里同时有 9.2，`find_toolchain` 可能选 9.2（`docs/07` §2）。本方案固定 11.2 并已实测 |
| binutils | 随工具链（2.37.20220122） | — |
| 内核 | 6.1.31 | 分支 `orange-pi-6.1-sun50iw9` |
| 主机依赖 | flex/bison/m4/bc/openssl/pahole/mkimage | Ubuntu 22.04 可 `apt install` |

> 官方 .config 的 `CONFIG_CC_VERSION_TEXT` 来自 Ubuntu 11.4 编译器，但 `olddefconfig` 会更新为 11.2；
> 两者 ABI 兼容，实测编译/加载通过（见 [docs/10](10_内核构建验证.md)）。

### 7.2 安装（两条路）

```bash
# A. 有 sudo 的正常开发机
sudo apt install -y build-essential flex bison bc libssl-dev libelf-dev \
                    kmod u-boot-tools device-tree-compiler
./scripts/setup_toolchain.sh          # 下载 Arm GNU 11.2 到 tools/

# B. 无 sudo（本机环境）
./scripts/setup_toolchain.sh
./scripts/setup_kernel_deps.sh        # flex/bison/m4/mkimage 解包到 tools/local
```

`setup_kernel_deps.sh` 会处理 Ubuntu `bison` 把 m4 路径写死为 `/usr/bin/m4` 的问题（改为相对 `m4` 走 PATH）。


最终验证是“能用这套工具链编出可加载的内核与模块”，见 §9 与 [docs/10](10_内核构建验证.md)。

## 8. 编译方案

### 8.1 一条命令（推荐）

```bash
./scripts/build_kernel.sh --jobs 8
```

脚本做的事（与 SDK 一致的最小集合）：

1. 检查工具链/`flex bison m4 mkimage`；
2. 没有源码则浅克隆 `orange-pi-6.1-sun50iw9` 到 `kernel/src/linux-6.1`；
3. `cp external/config/kernel/linux-6.1-sun50iw9-next.config .config` + `olddefconfig`；
4. `make -j8 ARCH=arm64 CROSS_COMPILE=... LOCALVERSION=-sun50iw9 Image modules dtbs`；
5. 收集 `Image`、`sun50i-h618-orangepi-zero3.dtb`、`System.map`、`.config`、`modules/` 到 `kernel/out/6.1/`。

常用参数：`--branch 5.4`、`--config my.config`、`--clean`、`--image Image`（arm64 官方即 `Image`；`zImage` 是 armhf 默认，不适用于本板）、`--jobs N`。

### 8.2 等价的纯命令（不依赖脚本）

```bash
export PATH=$PWD/tools/local/usr/bin:$PATH
CROSS=$PWD/tools/gcc-arm-11.2-2022.02-x86_64-aarch64-none-linux-gnu/bin/aarch64-none-linux-gnu-
cd kernel/src/linux-6.1
cp ../../vendor/orangepi-build/external/config/kernel/linux-6.1-sun50iw9-next.config .config
make ARCH=arm64 CROSS_COMPILE=$CROSS olddefconfig
make -j$(nproc) ARCH=arm64 CROSS_COMPILE=$CROSS LOCALVERSION=-sun50iw9 Image modules dtbs
```

### 8.3 与“完整 SDK（orangepi-build）”的分工

| 事项 | 本方案 | orangepi-build |
|---|---|---|
| 内核 Image/dtb/modules | ✅ 独立完成 | ✅ |
| rootfs / 发行版 | ❌（用官方镜像） | ✅ debootstrap |
| U-Boot / ATF / 启动脚本 | ❌（用官方镜像/预编译） | ✅ |
| deb 打包 | 可选（`make bindeb-pkg`） | ✅ bindeb-pkg |
| 适用 | 改驱动/DTS/快速迭代 | 出整机镜像 |

### 8.4 更新到板子

```bash
# 只换内核 + 模块（保留官方 rootfs）
scp kernel/out/6.1/Image orangepi@<IP>:/tmp/
scp kernel/out/6.1/sun50i-h618-orangepi-zero3.dtb orangepi@<IP>:/tmp/
scp -r kernel/out/6.1/modules/lib/modules/6.1.31-sun50iw9 orangepi@<IP>:/tmp/modules/
ssh orangepi@<IP> 'sudo cp /tmp/Image /boot/; ...'   # 具体路径随镜像而异，先 ls /boot
```

> 更稳的方式是 `make bindeb-pkg` 出 `linux-image-*.deb`，在板子上 `dpkg -i`；官方镜像的
> `/boot` 布局与 U-Boot 启动脚本会处理 `Image`/`dtb` 位置。改动前先备份并确认串口可救砖。

## 10. 风险与排错

### 10.1 编译期

| 现象 | 原因 | 处理 |
|---|---|---|
| `bison: m4 subprocess failed` | Ubuntu bison 写死 `/usr/bin/m4`，而 m4 不在 | `scripts/setup_kernel_deps.sh`（改相对路径） |
| `mkimage: not found`（dtbs 阶段） | 没装 u-boot-tools | `apt install u-boot-tools` 或本地解包 |
| `scripts/extract-cert` / openssl 错误 | 缺 libssl-dev | 安装；或关 `MODULE_SIG`（不推荐量产） |
| `pahole` 相关 BTF 错误 | 缺 pahole 或版本老 | 关 `DEBUG_INFO_BTF` 或装 dwarves |
| 改了内核源码但 SDK 不重编 | `output/debs/` 里已有同名 deb 会跳过 | 删掉对应 `linux-image-next-sun50iw9_1.0.6_arm64.deb` 再编 |
| OOM / 编译被 kill | 8GB 内存 + 大 .config | 降 `-j`、加 swap、裁剪配置 |
| 源码改动被覆盖 | SDK 同步 | `IGNORE_UPDATES="yes"` |

### 10.2 运行期

| 现象 | 原因 | 处理 |
|---|---|---|
| `version magic ... should be` | 模块与内核不是同一次编译/LOCALVERSION 不一致 | 用同一棵树、同一 `LOCALVERSION=-sun50iw9` 重编 |
| 无 WiFi | 主线内核没驱动 / 模块没装 | 厂商 6.1 树；`modprobe uwe5622_bsp_sdio sprdwl_ng sprdbt_tty` |
| 无 HDMI | 主线 DTS 无 HDMI/DE 节点 | 用厂商 6.1 树 |
| 网口能拿 IP 不能传数据 | RGMII delay 参数不全 | 加 `rgmii-rxid` + `tx-delay-ps=700` + `clk-out-frequency=125MHz` |
| 开机 hang | 主线 AXP313 中断 parent 写成 `&pio` | 带 `&r_pio` 补丁（未合入，见 docs/08 §4.2） |
| 26pin 功能没有 | dtbo 没加载 | `orangepi-config` 勾选；或检查 `/boot/.../overlay` 与启动参数 |
