## 2. 验证方法与结果

### 2.1 一键复现

```bash
./scripts/verify_all.sh
```

最近一次结果：**PASS=28 FAIL=0 SKIP=0**；资产校验另计 **OK=58 FAIL=0**（`scripts/validate_assets.py --strict`）。原始输出见 `docs/evidence/verification.log`。

### 2.2 编译层

| 验证 | 方法 | 结果 |
|---|---|---|
| 交叉编译 | `make -C examples`（aarch64-none-linux-gnu-gcc 11.2） | 6 个程序全部成功，**0 warning / 0 error** |

### 2.3 运行层（qemu 用户态）

| 验证 | 方法 | 结果 |
|---|---|---|
| 动态链接/glibc ABI | `qemu-aarch64 -L <toolchain-sysroot> ./prog --help` | 6/6 正常退出 |

> 说明：qemu 只能验证“程序逻辑 + ABI”，不能替代 GPIO/I2C/SPI/PWM 的真实电气与时序验证。

### 2.6 手册/原理图交叉核对（人工 + 工具）

| 核对项 | 结论 |
|---|---|
| 页码偏移 | 印刷页 = PDF 物理页 − **9**；用 340 个页脚逐页验证，零例外（`docs/evidence/manual_extract.md`） |
| 26pin 表 vs 原理图 | 17 个 GPIO 的信号名/顺序/引脚完全一致；GPIO 号与公式一致 |
| 13pin 表 vs 原理图 | 300dpi 裁图逐脚核对，1–13 完全一致（PC1/PI16/PI6/IR-RX） |
| 13pin 复用 | PI6 的 I2C0/UART2 需要未引出的 PI5，实际只能当 GPIO；**PI16 在 `ext_rgmii_pins` 组内（emac0），以太网启用时可能被复用为 EPHY_25M，作 GPIO 可能 EBUSY**，需实测（`docs/03` D8） |
| PC9 | **重要发现**：原理图 Sheet 1 上 PC9 经 R42(0Ω) 接 AXP313A **PMU_IRQ**，不适合做普通输出；文档已把点灯示例改为 PC7(22 脚) |
| PC5/PC6 | 分别是 BOOT_SEL3/BOOT_SEL4 启动脚（10K 下拉/上拉），上电瞬间电平参与启动模式 |
| Wi-Fi 模块 | 已结案（2026-11 调研）：`20U5622` 是 CdTech 模块型号，die=`AW859A`=`UWE5622` 同一颗芯片；厂商 6.1 树内自带驱动，主线无。见 `docs/08` §3 |
| SPI Flash 容量 | 手册 P2 写 16MB，原理图 U61 `ZB25VQ16` = **16Mbit/2MB**（差 8 倍）→ 文档已标注矛盾，需 `cat /proc/mtd` 实测 |
| 电源 | AXP313A（3×DCDC + 2×LDO）；Type-C 仅 5.1K CC 下拉、无 PD 协商；26pin/13pin 的 5V 直连 VBUS |
| 以太网 | YT8531C、RGMII、25MHz、PHY addr=1 |

## 3. 必须在真板复测的项目（本仓库未验证）

| # | 项目 | 为什么不能在这里验证 | 复测方法 |
|---|---|---|---|
| H1 | GPIO 实际电平/驱动能力 | 无板、qemu 无 gpio 设备 | `gpio_blink` + 万用表/LED；测 3.3V 与灌/拉电流 |
| H2 | GPIO 中断/消抖 | 同上 | `gpio_event` + 按键/信号发生器 |
| H3 | UART5 真实收发 | PTY 只验证逻辑 | 短接 8/10 脚跑 `uart --loopback`；再接 USB-TTL 对测 |
| H4 | I2C3 时序/上拉/速率 | qemu 无 i2c | `i2c_scan` + 逻辑分析仪；验证 100k/400k |
| H5 | SPI1 模式/CS/速率上限 | qemu 无 spidev | `spi_loopback` 短接 19/21；逐步提速找上限 |
| H6 | PWM 波形/频率精度 | qemu 无 pwmchip | 示波器测 10 脚/8 脚；50Hz–1kHz |
| H7 | 以太网吞吐/延迟 | 无板 | `iperf3` 双向；确认 `phy-mode=rgmii` 与 delay 参数 |
| H8 | Wi-Fi/BT 可用性 | 模块型号存疑 | `nmcli`/`bluetoothctl`；先确认 U60 丝印 |
| H9 | HDMI 分辨率/音频 | 无显示设备 | 接显示器；`aplay` 经 13pin 扩展板 |
| H10 | 温度/降频/长时间稳定性 | 无板 | 满载 1h，`thermal_zone*` + `scaling_cur_freq` |
| H11 | 看门狗 | 无板 | `watchdog_test 10` 不喂狗应重启 |
| H12 | USB Host 供电能力 | 无板 | 接 U 盘/摄像头/移动硬盘，测 VBUS 电压跌落 |
| H13 | 内核 5.4 差异 | 只分析了 6.1 DTS | 5.4 镜像复跑 F 矩阵；注意 `/dev/ttyAS5` 命名 |
| H14 | 13pin 扩展板行为 | 无扩展板 | 插板后确认 10/11/12 不可用、IR/音频/USB 正常 |
| H16 | 13pin 11 脚 PI16 能否作 GPIO | 与 emac0 的 `ext_rgmii_pins` 重叠 | `gpio_blink -l 272` 试申请；若 EBUSY，试禁用/裁剪 emac0 pinctrl 后复测以太网 |
| H15 | 上电时序/复位 | 无板 | 示波器测各 rail 上电顺序、复位脉宽 |

> 这些项目不是“没做”，而是**只能硬件在环**。建议按 `docs/00_开发准备清单.md` 的 F 表逐项打勾。

## 4. 已知限制与说明

1. **本机没有连接开发板**：`/dev/ttyUSB0` 存在但无对端输出，因此未做任何上板测试。
2. **qemu 不是板子**：只覆盖用户态逻辑与 ABI；GPIO 字符设备、I2C、SPI、PWM、网络 PHY 都不在验证范围内。
3. **原理图第 7 页与 SDK 不一致**：Wi-Fi 模块型号存在 AW859A / UWE5622 两种证据，未下结论；上板读 U60 丝印为准。
4. **手册本身有 7 处排版/口径矛盾**（页码、wPi 编号、28/30 定义等），已在 `docs/01`/`docs/03` 就地标注，未擅自“统一”。
5. **Android/OpenWRT** 只做了手册信息抽取，未编译验证（环境要求与 Linux SDK 不同）。
6. 所有“推断/未确认”均保留标记，未用猜测填充数据。
