# 17 · Orange Pi Zero 3 的显示输出链路

> 问题：Zero3 的画面是怎么从 SoC 送到 HDMI 屏的？硬件走哪些模块、Linux 下由谁驱动、能到什么分辨率、
> 有哪些板级坑？本文按“硬件 → 驱动 → 用户态 → 调试”四层说明。
>
> 一句话：**H618 的显示引擎（DE）合成图层 → TCON 时序 → DW-HDMI 控制器 → TMDS PHY → Micro HDMI 座**；
> Linux 下由 **厂商 6.1 的 DRM/KMS（sun4i-drm + dw-hdmi）** 驱动；**主线到 7.4 仍没有 HDMI/DE 节点**，
> 所以 Linux 出画面必须用厂商 6.1 树（或 Android 的 display2 栈）。

---

## 0. 结论速览

| 项 | 结论 |
|---|---|
| 物理接口 | 板上 1 个 **Micro HDMI（Type-D，19 pin + 4 shield）**；无 DSI/DP |
| SoC 显示模块 | **DE（Display Engine）** + **TCON** + **HDMI 控制器（DW-HDMI）** + **HDMI PHY（TMDS）** |
| 最大输出 | HDMI 2.0a，标称 **4K@60**；工程建议 1080p60（4K 受 UI/带宽/散热限制） |
| Linux 驱动 | 厂商 6.1：`sun4i-drm` + `sun8i_mixer` + `sun8i_tcon_top` + `sun8i_dw_hdmi` + `dw-hdmi` + `sun8i_hdmi_phy` |
| 主线 | **无 HDMI/DE 节点**（到 7.4-rc1 仍无）→ 主线 Linux 无显示输出 |
| Android | 厂商 display2/HDMI2 栈，HDMI 视频/音频 OK（手册 P303） |
| 音频 | HDMI 内嵌音频：DW-HDMI I2S/AHB audio + `SND_SOC_HDMI_CODEC`，走同一个 HDMI 口 |
| 其他输出 | 13pin 有 **TV-OUT（CVBS）**，但 Linux 无驱动（手册标 NO）；Android 可用 |
| 板级注意 | HDMI-5V 经 D5 肖特基从 VCC-5V 取电；HPD 经 1K 直入 SoC；原理图未见 ESD 器件符号；Micro HDMI 与 Type-C 间距小 |

## 1. 硬件链路

### 1.1 模块框图

```
CPU/GPU/VPU 产生像素
        │  framebuffer / DMA-BUF（NV12/RGB）
        ▼
┌──────────────────────── H618 SoC ────────────────────────┐
│  DE (Display Engine, DE2/DE3)                             │
│   ├─ 多个 layer/plane（UI、video overlay）                │
│   ├─ mixer：alpha blending、scaler、颜色空间              │
│   └─ 输出到 TCON                                          │
│  TCON（Timing Controller）：像素时钟/行场时序             │
│  HDMI 控制器（DesignWare DW-HDMI）：打包 TMDS、音频、CEC  │
│  HDMI PHY：并串转换/TMDS 驱动                             │
└───────────────────────────┬──────────────────────────────┘
                            │ 4 对 TMDS（D0/D1/D2/CLK 差分）
                            │ HPD、DDC(SCL/SDA)、CEC、+5V
                            ▼
                  Micro HDMI Type-D 座 → HDMI 线 → 显示器/电视
```

### 1.2 原理图上的连接（Sheet 5）

- **TMDS**：`HTX0P/N`、`HTX1P/N`、`HTX2P/N`、`HTXCP/N` 四对差分，直接进 Micro HDMI 座；
- **HPD（热插拔）**：`HHPD` 经 **RH5 1K** 串联到连接器 HPD 脚（SoC 侧检测）；
- **DDC**：`HDMI0_TX_SCL_PORT` / `HDMI0_TX_SDA_PORT` 直连连接器 SCL/SDA（读 EDID）；
- **CEC**：`HDMI0_TX_CEC_PORT` 连到 CEC 脚（可选，Linux 有 `DRM_DW_HDMI_CEC=m`）；
- **+5V**：`VCC-5V` 经 **D5 B5819WS 肖特基** → `HDMI-5V` → 连接器 5V 脚（给显示器 EDID/热插拔供电，防倒灌）；
- **ESD**：图上只见两处文字 “0721”，**没有看到 ESD 阵列器件符号**（docs/02 R9 已标“需实物核对”）；
- 连接器是 **19 pin + 4 个 shield 脚（20–23）** 的 Micro HDMI Type-D 封装。

> 板级风险：HPD 是 sink 侧 5V 信号，经 1K 直接进 SoC（未见分压/钳位）；DDC 也直连。
> 长期热插拔/静电环境建议外加 ESD/电平保护（改板时）。

### 1.3 供电与热插拔

- HDMI-5V 只从板子的 VCC-5V 经肖特基取电，**没有独立限流**；短路/大电流会拉低整板 5V；
- HPD 决定是否有显示器：SoC 通过 HPD 电平判断插拔，再读 EDID 拿分辨率；
- Micro HDMI 与 Type-C 电源口间距小，**宽头转接头可能插不进去**（手册 P7）。

## 2. 软件链路（Linux）

### 2.1 厂商 6.1：DRM/KMS

设备树（`sun50i-h616.dtsi` + 板级 DTS）：

```dts
de: display-engine {
    compatible = "allwinner,sun50i-h6-display-engine";
    allwinner,pipelines = <&mixer0>;
    status = "disabled";          // 板级 &de { status = "okay"; }
};

hdmi: hdmi@6000000 {
    compatible = "allwinner,sun50i-h616-dw-hdmi",
                 "allwinner,sun50i-h6-dw-hdmi";
    phys = <&hdmi_phy>;
    status = "disabled";          // 板级 &hdmi { status = "okay"; }
};
```

板级 `sun50i-h618-orangepi-zero3.dts` 把 `&de`、`&hdmi` 都设为 `okay`，并连好 `hdmi_out ↔ hdmi_con_in`。

内核配置（6.1 官方）：

```
CONFIG_DRM_SUN4I=y
CONFIG_DRM_SUN8I_DW_HDMI=y
CONFIG_DRM_SUN8I_MIXER=y
CONFIG_DRM_SUN8I_TCON_TOP=y
CONFIG_DRM_DW_HDMI=y
CONFIG_DRM_DW_HDMI_I2S_AUDIO=y
CONFIG_DRM_DW_HDMI_CEC=m
CONFIG_SND_SOC_HDMI_CODEC=y
CONFIG_DRM_FBDEV_EMULATION=y
CONFIG_FRAMEBUFFER_CONSOLE=y
```

驱动栈：

| 层 | 驱动 |
|---|---|
| DRM 主设备 | `sun4i_drv`（`drivers/gpu/drm/sun4i/sun4i_drv.c`） |
| 合成/图层 | `sun8i_mixer`（DE2/DE3 mixer、plane、alpha、scaler） |
| 时序 | `sun4i_tcon` + `sun8i_tcon_top` |
| HDMI 控制器 | `sun8i_dw_hdmi` + `dw-hdmi`（bridge） |
| HDMI PHY | `sun8i_hdmi_phy` |
| 音频 | `dw-hdmi-i2s-audio` + `SND_SOC_HDMI_CODEC` |
| CEC | `dw-hdmi-cec`（模块） |

用户态看到的是标准 DRM 设备：`/dev/dri/card0`、`/dev/dri/renderD128`；
fbdev 模拟提供 `/dev/fb0`，所以启动时 HDMI 上能看到 **内核 console/getty**。

### 2.2 主线：没有显示

- 主线 `sun50i-h616.dtsi` 到 **7.4-rc1 仍没有 `hdmi@`/`display-engine` 节点**（docs/08 §2）；
- 因此主线内核即使 USB/网卡/CPU 都正常，**HDMI 无输出**；
- 想用主线只能自己移植 DE/HDMI 驱动 + DTS，工作量大于收益。

### 2.3 Android

- Android 12 TV 用厂商 **display2/HDMI2** 框架（不是 DRM），HDMI 视频/音频、4K、HDR 由厂商栈处理；
- 手册 8.2（P303）标 HDMI 视频/音频 OK；
- Miracast/投屏、UI 都走 Android SurfaceFlinger → display2 → HDMI。

## 3. 分辨率、格式与带宽

| 项 | 说明 |
|---|---|
| 最大 | HDMI 2.0a，标称 4K@60；TMDS 最高约 600MHz |
| 4K60 | 4:4:4 8bit 需要 ~594MHz TMDS；4:2:0 8bit 约 297MHz；具体以 EDID/驱动支持为准 |
| 1080p60 | 最稳；像素时钟 148.5MHz，带宽约 4.45Gbps（8bit RGB） |
| 色彩 | RGB / YCbCr 4:4:4 / 4:2:0；8bit；HDR 需驱动/显示栈支持（Linux 下未验证） |
| 图层 | DE 支持多 plane：UI（RGB）+ 视频（NV12）叠加；视频可用 overlay 免 GPU 合成 |
| 带宽 | 1080p60 有效像素约 3.0Gbps（TMDS 链路约 4.5Gbps）；4K60 有效约 12Gbps、TMDS 链路约 18Gbps；LPDDR4 12.8GB/s 共享，4K 时要注意 |
| 建议 | TV demo 固定 **1080p60**；4K 只在确认 EDID/线材/散热后试 |

### 3.1 零拷贝视频路径

```
cedrus 解码 → DMA-BUF (NV12) → DRM plane → DE mixer → TCON → HDMI
```

GStreamer 的 `kmssink` 可以直接用 DMA-BUF，避免“解码→CPU 拷贝→GPU 纹理”的额外带宽；
这是 1080p 播放省 CPU/带宽的关键。

## 4. HDMI 音频

- DW-HDMI 内置音频接口（I2S/AHB），通过 HDMI 的 data island 传输；
- Linux 下表现为一个 ALSA card（`aplay -l` 可看到 HDMI）；
- 依赖：
  - `CONFIG_DRM_DW_HDMI_I2S_AUDIO=y`
  - `CONFIG_SND_SOC_HDMI_CODEC=y`
  - 板级 DTS 的 `hdmi` 节点 + `hdmi_out` 连接；
- 音频路由由 EDID/ELD 决定（显示器支持几声道）；GStreamer 用 `alsasink device=hdmi:...`。

> 如果 HDMI 无声：先 `aplay -l` 看 card，再 `speaker-test -D hw:X,Y`；不要同时让 PulseAudio 抢占。

## 5. 其他显示输出

| 输出 | 位置 | Linux | Android |
|---|---|---|---|
| Micro HDMI | 板载 | ✅ 厂商 6.1 DRM | ✅ |
| TV-OUT（CVBS） | 13pin | ❌ 无驱动（手册标 NO） | ✅ |
| MIPI DSI | SoC 有，板子未引出 | — | — |
| USB 显示 | USB2.0 | 可用 DisplayLink 等（CPU 重） | 视驱动 |

> TV-OUT 在 Linux 下不可用；不要把它当第二显示方案。

## 6. 调试与使用命令

```bash
# 1) 连接状态 / EDID / 支持模式
cat /sys/class/drm/card0-HDMI-A-1/status
cat /sys/class/drm/card0-HDMI-A-1/modes
cat /sys/class/drm/card0-HDMI-A-1/edid | hexdump -C | head

# 2) DRM 设备与能力
modetest -M sun4i-drm
modetest -M sun4i-drm -c        # 连接器
modetest -M sun4i-drm -p        # plane

# 3) 驱动日志
dmesg | grep -iE "sun4i-drm|dw-hdmi|hdmi|tcon|edid"

# 4) 强制 1080p60（fbdev 控制台）
#    内核 cmdline 加：video=HDMI-A-1:1920x1080@60
#    或在 DRM 用户态用 modetest/wlr-randr 切模式

# 5) HDMI 音频
aplay -l
speaker-test -D hw:0,0 -c 2 -t sine -l 1

# 6) 简单测试图（GStreamer）
gst-launch-1.0 videotestsrc ! video/x-raw,width=1920,height=1080 \
  ! kmssink force-modesetting=true
```

### 6.1 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `status=disconnected` | 线/口/HPD/供电 | 换细头 Micro HDMI 线；确认显示器 HPD；量 HDMI-5V |
| 有画面但分辨率不对 | EDID 未读到/线材差 | 换线；`modetest` 看 modes；强制 `video=HDMI-A-1:1920x1080@60` |
| 黑屏但 dmesg 正常 | 无 DRM master/console 占用 | 停桌面/getty；用 `kmssink`；确认 `de`/`hdmi` okay |
| 4K 花屏/闪断 | TMDS 带宽/线材/散热 | 降 1080p；换 HDMI 2.0 认证线；加散热 |
| HDMI 无声 | 音频路由/PulseAudio | `aplay -l`；禁用 PulseAudio；`alsasink device=` |
| 主线内核无 HDMI | 主线无 DE/HDMI 节点 | 用厂商 6.1（docs/08/09） |

## 7. 对 TV/投屏 demo 的影响

- **Linux 出画面必须用厂商 6.1 内核**；主线 7.4 无 HDMI/DE，不能做 TV。
- `kmssink` 直出要求没有 X/Wayland/桌面抢 DRM master；Debian minimal 最合适（docs/16）。
- 1080p60 是稳妥目标；4K 只作为可选验证。
- HDMI 音频与视频同一个口，播放器要正确选 `alsasink` 设备。
- 原理图没有明显 ESD 器件、HPD 直连 SoC：做产品/频繁热插拔时要评估保护。
