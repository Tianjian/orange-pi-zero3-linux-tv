## 1. 板卡规格

### 1.1 硬件特性表（照抄手册，勿改型号）

| 分类 | 规格 |
|---|---|
| CPU | 全志 H618 四核 64 位 1.5GHz 高性能 Cortex-A53 |
| GPU | Mali G31 MP2；Supports OpenGL ES 1.0/2.0/3.2、OpenCL 2.0 |
| 内存 | 1GB / 1.5GB / 2GB / 4GB LPDDR4（与 GPU 共享） |
| 板载存储 | TF 卡插槽、16MB SPI Flash（⚠️ 原理图器件 ZB25VQ16 实为 16Mbit=2MB，见 §1.1 注） |
| 以太网 | 支持 10/100M/1000M |
| WIFI+蓝牙 | 20U5622 芯片、支持 IEEE 802.11 a/b/g/n/ac、BT5.0 |
| 视频输出 | Micro HDMI 2.0a；TV CVBS output，支持 PAL/NTSC（通过 13pin 扩展板） |
| 音频输出 | Micro HDMI 输出；3.5mm 音频口（通过 13pin 扩展板） |
| 电源 | USB Type C 接口输入 |
| USB 2.0 端口 | 3 个 USB 2.0 HOST（其中两个通过 13pin 扩展板） |
| 26pin 接头 | I2C×1、SPI×1、UART×1 以及多个 GPIO 口 |
| 13pin 接头 | USB 2.0 HOST×2、TV-OUT、LINE OUT、IR-RX 以及 3 个 GPIO 口 |
| 调试串口 | UART-TX、UART-RX 以及 GND |
| LED 灯 | 电源指示灯和状态指示灯 |
| 红外接收 | 支持红外遥控器（通过 13pin 扩展板） |
| 支持的操作系统 | Android12 TV、Ubuntu、Debian 等 |

（手册 P2 / PDF 第11页）

### 1.2 尺寸与机械

- PCB 尺寸 **50mm × 55mm**，重量约 **30g**（手册 P2 / PDF 第11页）。
- **四个定位孔直径都是 3.0mm**（手册 P5 / PDF 第14页）。
- 顶层/底层视图、接口详情图只有图片，无文字标注（手册 P3–P4 / PDF 第12–13页）。

> 结论：外壳/结构件按 50×55mm、M3 以下螺钉、孔距需自己量板（手册未给定位孔坐标）。

## 2. 接口与供电

### 2.1 供电（最容易翻车的地方）

**推荐接法**：5V/2A 或 5V/3A 高品质 Type-C 电源适配器插 Type-C 口。

手册原文警告：
- “切记不要插入电压输出大于 5V 的电源适配器，会烧坏开发板。”
- “系统上电启动过程中很多不稳定的现象基本都是供电有问题导致的”——启动中反复重启，先换电源/Type-C 线。

（手册 P29 / PDF 第38页）

**用 26pin / 13pin 的 5V 引脚反灌供电**（P37 / PDF 第46页）：
- 红线 → 26pin 或 13pin 的 **5V** 引脚；黑线 → **GND** 引脚；USB-A 端接 5V/2A~3A 适配器。
- 不建议插电脑 USB 口供电（外设多会不稳）；不稳定就换回 Type-C。

```text
26pin/13pin 5V 供电：红线->5V 引脚，黑线->GND 引脚，模块端接 5V/2A 适配器
切记得确认 5V/GND 位置，接反会烧板（手册 P37）
```

### 2.2 USB

- 板上只有 **1 个 USB2.0 HOST**；另外 **2 个 USB2.0 HOST 通过 13pin 扩展板**提供（P2 / PDF 第11页）。
- 没有 13pin 扩展板时，可用 **4pin 2.54mm 杜邦转 USB2.0 母头**线从 13pin 的 `USB2-DM/DP`、`USB3-DM/DP` 引出（P38 / PDF 第47页）。13pin 引脚号见 `docs/03`。

### 2.3 显示与音频

- Micro HDMI 2.0a 直出 HDMI；**不要用偏宽的 Micro HDMI 转接头**，因为 Micro HDMI 与 Type-C 之间间距小，可能插不进（P7 / PDF 第16页）。
- HDMI 转 VGA 有专门测试章节（P91 / PDF 第100页）。
- TV-OUT（CVBS，PAL/NTSC）与 3.5mm 音频口都**只能经 13pin 扩展板**（P2、P112 / PDF 第11、121页）。
- ⚠️ Linux 下 **TV-OUT 驱动状态为 NO**（5.4 与 6.1 都是），见 §4.2；Android 12 下 TV-OUT 为 OK（P303 / PDF 第312页）。

### 2.4 调试串口接线（必做）

```text
USB-TTL(3.3V)          Orange Pi Zero 3 调试串口
GND      ────────────  GND
RX       ────────────  TX   (交叉)
TX       ────────────  RX   (交叉)
```

- 必须用 **3.3V 电平**的 USB 转 TTL 模块（P11 / PDF 第20页）。
- 串口软件参数（手册 P32 / PDF 第41页）：`Serial line = /dev/ttyUSB0`（按实际节点）、`Speed(baud) = 115200`、`Flow control = None`。
- 数据位/校验/停止位**手册未写明**（PuTTY 默认 8N1，见待确认清单）。
- Windows 侧可用 SecureCRT / MobaXterm 等（P34 / PDF 第43页）。

### 2.5 红外接收

- 必须插 **13pin 扩展板**才能用红外（P108 / PDF 第117页）。
- 必须用 **Orange Pi 专用红外遥控器**，其他遥控器不支持（P109 / PDF 第118页）。
- 验证：
  - Linux 5.4：`sudo ir-keytable -t`，能看到 `scancode = 0xfb0413` 一类输出（P110 / PDF 第119页）。
  - Linux 6.1：`sudo ir-keytable -c -p NEC -t`，输出 `lirc protocol(nec): scancode = 0x45c`。

## 3. 启动流程与启动介质

### 3.1 三种“系统”来源

| 来源 | 说明 | 出处 |
|---|---|---|
| SPI Flash（手册标称 16MB，器件实为 16Mbit/2MB） | 出厂烧有微型 Linux，**不插 TF 卡**接 Type-C 就能启动；u-boot 阶段红灯亮，进内核后红灯灭、绿灯闪；接 HDMI 有命令行，可接 USB 键盘敲 `ls`/`cd` | P28 / PDF 37 |
| TF 卡 | 烧 Debian/Ubuntu/Arch/OpenWRT 镜像后启动完整系统 | P29 / PDF 38 |
| Android | Android12 TV 镜像烧到 TF 卡（Windows + PhoenixCard 4.2.8） | P22 / PDF 31 |

- SPI Flash 的微型系统只用于“证明板子能正常启动”，功能有限，要全功能必须烧 TF 卡（P28 / PDF 第37页）。
- ⚠️ **容量疑点**：原理图 Sheet 1 的 U61 丝印为 `ZB25VQ16ASIG`，`25VQ16` = 16Mbit = **2MB**，与手册 P2 的“16MB”差 8 倍。以器件型号为准更可信，上板可用 `cat /proc/mtd` 实测分区大小确认。
- 若 SPI Flash 被清空，则无卡上电时两个 LED 都不亮（P47 / PDF 第56页）。

### 3.2 启动介质优先级

⚠️ **手册未给出启动介质优先级/BOOT 顺序表**（未在 1.x/2.x/附录中出现），只说明「无 TF 卡时启动 SPI Flash 里的微型系统，插卡后启动卡内系统」（P28–P29 / PDF 第37–38页）。
实测确认请用串口看 u-boot 打印，或直接参考全志 H618 BSP 的 boot 顺序——**本仓库未确认，勿写进生产文档**（见待确认清单）。

### 3.3 上电启动检查清单

1. 烧好镜像的 TF 卡插到底（P29 / PDF 第38页）。
2. 可接 Micro HDMI 显示器、13pin 扩展板、USB 键鼠、网线。
3. 接 5V/2A（或 5V/3A）Type-C 电源，开电源开关。
4. HDMI 有启动画面 = 正常；想看内核 log 就接调试串口（§2.4）。
5. 判断系统是否正常启动的土办法：**绿灯在闪**一般就是正常启动；只亮红灯或都不亮说明没起来（P62 / PDF 第71页）。

## 5. 烧写镜像

### 5.1 Linux 镜像（Windows）

balenaEtcher 或 Win32Diskimager，`.img` 文件写入 TF 卡（P12、P15 / PDF 第21、24页）。

### 5.2 Linux 镜像（Ubuntu PC）

```bash
7z x orangepizero3_1.0.0_ubuntu_focal_desktop_linux6.1.31.7z
sha256sum -c *.sha                      # 必须先校验，提示“成功”才烧
# 然后用 balenaEtcher（AppImage 双击即可，无需安装）写入 TF 卡
```

（手册 P19 / PDF 第28页）

### 5.3 Android 镜像（只能 Windows）

- 只支持 **Windows + PhoenixCard 4.2.8**；**不能用 balenaEtcher / Win32Diskimager / dd**。
- PhoenixCard 没有 Linux/Mac 版本，Linux/Mac 下无法烧 Android。
- 需先装 Microsoft Visual C++ 2008 Redistributable x86。

（手册 P22 / PDF 第31页）

### 5.4 TF 卡选择（血泪坑）

- 最小 **8GB、class10 及以上**，**强烈建议闪迪**。
- 手册明确列出“非闪迪卡导致启动到一半卡住 / `reboot` 命令失效”的案例，详见 P6 图片；在其它板子上能用的卡不代表 Zero 3 能用。

（手册 P6 / PDF 第15页）

## 6. 登录与远程访问

### 6.1 默认账号密码（手册 P43 / PDF 第52页）

| 账号 | 密码 |
|---|---|
| root | orangepi |
| orangepi | orangepi |

- 终端**默认自动登录**，默认用户 `orangepi`（P43 / PDF 第52页）。
- 桌面版可用 `sudo desktop_login.sh root` 改成 root 自动登录桌面（此后右上角 pulseaudio 不可用，是 pulseaudio 限制不是 bug）；反向命令 `sudo disable_desktop_autologin.sh` 会恢复登录对话框（P45–P46 / PDF 第54–55页）。

### 6.2 SSH

- Linux 镜像**默认开启 SSH，且允许 root 登录**（P87 / PDF 第96页）。

```bash
ssh orangepi@192.168.1.xxx      # 密码 orangepi
# 或
ssh root@192.168.1.xxx          # 密码 orangepi
```

- 连不上先 `ping` 通，再在板子上跑 `sudo reset_ssh.sh` 重试，仍不行再重烧（P88 / PDF 第97页）。
- 密码输错/被拒时，手册的口径是：只要用的是官方镜像，先别怀疑密码，去找网络/镜像原因。

## 7. 网络配置

### 7.1 以太网

- 插网线即 **DHCP 自动获取**，无需任何配置（P62 / PDF 第71页）。

```bash
ip a s eth0            # debian12 / ubuntu24.04 上节点名是 end0：ip a s end0
ping www.baidu.com -I eth0        # ubuntu24.04: -I end0
```

### 7.2 WiFi（服务器版命令行方式）

```bash
nmcli dev wifi                                                # 扫描
sudo nmcli dev wifi connect <wifi_name> password <wifi_passwd>  # 连接
ip a s wlan0                                                  # 查 IP
```

（手册 P64 / PDF 第73页）

> ⚠️ 手册明确：**不要**通过改 `/etc/network/interfaces` 连 WiFi 或设静态 IP，会有问题（P63、P76 / PDF 第72、85页）。

### 7.3 静态 IP

```bash
sudo nmtui
# Edit a connection -> 选 Wired connection 1 (或对应无线) -> <Edit>
# IPv4 的 <Automatic> 回车 -> 选 Manual -> 填 Address/Gateway/DNS -> OK -> 退出 -> 重启
```

（手册 P76–P78 / PDF 第85–87页；`nmcli` 方式见 P83 / PDF 第92页）

### 7.4 首次启动自动联网/自动设静态 IP

在烧好卡但**尚未首次启动**前，编辑 TF 卡 `/boot/orangepi_first_run.txt`：

```ini
FR_net_change_defaults=1
FR_net_wifi_enabled=1
FR_net_wifi_ssid=<SSID>
FR_net_wifi_key=<密码>
FR_net_use_static=1
FR_net_static_ip=<IP>
FR_net_static_gateway=<网关>
# 有线则用 FR_net_ethernet_enabled=1
```

- 只对**烧录后第一次启动**生效；首次启动后文件被删除或改名为 `orangepi_first_run.txt.old`，**再改也不会生效**（P87 / PDF 第96页）。

## 8. 板载 LED（sysfs 控制）

### 8.1 默认行为

| 阶段 | 绿灯 | 红灯 |
|---|---|---|
| u-boot 启动阶段 | 灭 | 亮 |
| 内核启动到进入系统 | 闪烁 | 灭 |
| GPIO | **PC13** | **PC12** |

（手册 P46–P47 / PDF 第55–56页）

### 8.2 手动控制（必须 root）

```bash
# 绿灯
cd /sys/class/leds/green_led
echo none       > trigger     # 停止闪烁
echo default-on > trigger     # 常亮
echo heartbeat  > trigger     # 闪烁

# 红灯
cd /sys/class/leds/red_led
echo default-on > trigger     # 常亮
echo heartbeat  > trigger     # 闪烁
echo none       > trigger     # 停止闪烁
```

（手册 P47 / PDF 第56页）

### 8.3 开机就不想要绿灯闪

```bash
sudo orangepi-config     # System -> Hardware -> 空格选中 disable-leds -> <Save> -> <Back> -> <Reboot>
```

重启后两个 LED 都不亮（手册 P48–P49 / PDF 第57–58页）。

## 9. 温度传感器 / 看门狗 / chipid

### 9.1 温度传感器（H618 共 4 个）

| sensor | 对应 | type 字符串 | 位置 |
|---|---|---|---|
| sensor0 | CPU | `cpu_thermal_zone` | /sys/class/thermal/thermal_zone0 |
| sensor1 | DDR | `ddr_thermal_zone` | thermal_zone1 |
| sensor2 | GPU | `gpu_thermal_zone` | thermal_zone2 |
| sensor3 | VE | `ve_thermal_zone` | thermal_zone3 |

**Linux 5.4**（手册 P110–P111 / PDF 第119–120页）：

```bash
cat /sys/class/thermal/thermal_zone0/type     # cpu_thermal_zone
cat /sys/class/thermal/thermal_zone0/temp     # 需要除以 1000，单位才是摄氏度
# zone1=DDR, zone2=GPU, zone3=VE 同理
```

**Linux 6.1**（手册 P111 / PDF 第120页）：

```bash
sensors
# cpu_thermal-virtual-0  temp1: +47.4°C (crit = +110.0°C)
# gpu_thermal-virtual-0  temp1: +48.7°C (crit = +110.0°C)
# ddr_thermal-virtual-0  temp1: +47.8°C (crit = +110.0°C)
# ve_thermal-virtual-0   temp1: +47.2°C (crit = +110.0°C)   <- 在下一页续行（P112）
```

> 坑：5.4 用 sysfs（原始值/1000），6.1 用 `lm-sensors`（℃ 直接可读）；6.1 的 `sensors` 输出跨页，四路传感器都在（VE 那一段印在 P112 页首）。

### 9.2 硬件看门狗

系统预装 `watchdog_test`：

```bash
sudo watchdog_test 10      # 第二个参数=计数时间(秒)，超时未喂狗则系统重启
# 按任意键（ESC 除外）喂狗，成功会打印 keep alive
```

输出里可见 `identity is sunxi-wdt`、`The old reset time is: 16`（手册 P149 / PDF 第158页）。

### 9.3 查看 H618 chipid

```bash
cat /sys/class/sunxi_info/sys_info | grep "chipid"
# sunxi_chipid      : 338020004c0048080147478824681ed1
```

每颗芯片 chipid 唯一，可用来区分多块板（手册 P150 / PDF 第159页）。

## 10. 26pin / 13pin 能力概述

> 逐脚定义、GPIO 序号、复用表 **不在本文重复**，见 `docs/03`（pinout 任务产物）；
> 原理图见 `docs/source/schematic.pdf`。

### 10.1 13pin 接口（P112–P113 / PDF 第121–122页）

不接扩展板时，**10、11、12、13 号引脚可当普通 GPIO**：

| GPIO 序号 | GPIO | 功能 | 引脚 |
|---|---|---|---|
| — | — | 5V | 1 |
| — | — | GND | 2 |
| — | — | USB2-DM / USB2-DP | 3 / 4 |
| — | — | USB3-DM / USB3-DP | 5 / 6 |
| — | — | LINEOUTR / LINEOUTL | 7 / 8 |
| — | — | TV-OUT | 9 |
| 65 | PC1 | PC1 | 10 |
| 272 | PI16 | PI16 | 11 |
| 262 | PI6 | PI6 | 12 |
| 234 | PH10 | IR-RX | 13 |

接扩展板后：额外得到 2×USB2.0 HOST、耳机左右声道、TV-OUT、红外接收；但 **10、11、12 号引脚就不能用了**，且扩展板上的 **MIC 在 Zero 3 上不可用**（P112 / PDF 第121页）。

### 10.2 26pin 接口能力（P113–P114 / PDF 第122–123页）

- 复用资源：**I2C3**（TWI3-SDA=PH5 / TWI3-SCK=PH4）、**SPI1**（CLK=PH6、MOSI=PH7、MISO=PH8、CS=PH9）、**UART5**（TX=PH2、RX=PH3）。
- **26pin 上共 17 个 GPIO，电平全部 3.3V**（P114 / PDF 第123页）。
- 供电引脚：1、17 脚 = 3.3V；2、4 脚 = 5V；6、9、14、20、25 脚 = GND。

### 10.3 复用功能默认是关的（新手最大坑）

> “26pin 中的 I2C/SPI/UART/PWM 等复用功能**默认在内核的 dts 中都是关闭的**，需要手动打开对应的 DT overlays 才能使用。”（P268 / PDF 第277页）

打开方法（Debian/Ubuntu 官方镜像）：

```bash
sudo orangepi-config
# System -> Hardware -> 方向键定位 + 空格勾选对应项 -> <Save> -> <Back> -> <Reboot>
```

对应勾选项与使能后节点：

| 功能 | `orangepi-config` 里勾 | 使能后设备节点 | 出处 |
|---|---|---|---|
| 26pin SPI1 | `spi1-cs1-spidev` | `/dev/spidev1.1` | P119–P120 / PDF 128–129 |
| 26pin I2C3 | （Hardware 中的 i2c3 项，手册仅截图未给选项名） | `/dev/i2c-3` | P121–P123 / PDF 130–132 |
| 26pin UART5 | `ph-uart5` | `/dev/ttyS5`（6.1）/ `/dev/ttyAS5`（5.4） | P124–P125 / PDF 133–134 |
| 硬件 PWM1/2 | `ph-pwm12` | `/sys/class/pwm/pwmchip0/pwm1`、`pwm2` | P126–P128 / PDF 135–137 |
| 硬件 PWM3/4 | `ph-pwm34` + `disable-uart0` | `pwm3`、`pwm4` | P127 / PDF 136 |
| 关 LED | `disable-leds` | — | P48 / PDF 57 |

**复用冲突（必须先想清楚）**（P127 / PDF 第136页）：

- PWM1、PWM2 与 26pin 的 **UART5 RX/TX** 复用 → 打开 `ph-pwm12` 就别勾 `ph-uart5`。
- PWM3、PWM4 与**调试串口** TX/RX（UART0）复用 → 用 `ph-pwm34` 必须先 `disable-uart0`，**之后调试串口就没了**。

### 10.4 wiringOP 的 GPIO 编号（简要）

- `gpio readall` 的 1~26 对应板上 26pin；27→13pin 10 号、29→13pin 11 号、31→13pin 12 号、33→13pin 13 号，28/30/32/34 手册写“为空，请直接忽略”（P115–P116 / PDF 第124–125页）。
- 但 PWM 章节给出的映射是 **PWM1=wPi 4、PWM2=wPi 3、PWM3=wPi 21、PWM4=wPi 22**（P131 / PDF 第140页），且新版 wiringOP 的 `gpio readall` “新增了 28 和 30 号引脚用来表示 PWM3 和 PWM4”（P129 / PDF 第138页）。
- 三处说法**互相矛盾**，完整可靠的对应表请以 `docs/03` + 板上实测 `gpio readall` 为准（见待确认清单）。
- 例：26pin **7 号引脚 = PC9 = wPi 2**（P116 / PDF 第125页）。

```bash
gpio mode 2 out      # 设为输出
gpio mode 2 in
gpio mode 2 up       # 上拉
gpio mode 2 down     # 下拉
gpio read 2          # 读电平
gpio readall         # 看全表（编号以此为准）
```

## 11. rootfs 容量与只读根（overlayroot）

### 11.1 自动扩容

- TF 卡烧完镜像后 rootfs 只有镜像大小，**第一次启动会自动把 rootfs 扩到整卡**；`df -h` 看到容量与卡容量一致即成功（P49 / PDF 第58页）。
- 想禁止自动扩容 / 手动扩容 / 缩小分区：P51–P57（PDF 第60–66页）。

### 11.2 overlayroot（防断电损毁文件系统）

- 目的：把 `/` 挂只读，修改落到可写层，异常断电不损坏原文件系统。
- 已测试：**Ubuntu Jammy / Focal / Noble、Debian Bookworm**；**Debian Bullseye 暂不支持**（P236 / PDF 第245页）。
- 两种可写层：`tmpfs`（重启即恢复原状）/ 块设备（如 U 盘、TF 卡分区，可持久化）。
- 开启：

```bash
sudo orangepi-config
# System -> Overlayroot -> tmpfs（或块设备）-> <Reboot>
mount | grep root        # 验证：/media/root-ro 只读层，/media/root-rw 可写层
```

- 关闭：`orangepi-config` 里改回，或改只读分区下 `/etc/overlayroot.conf` 的 `overlayroot=""`（P240 / PDF 第249页）。

### 11.3 系统备份

`opi-bkimg` 脚本可把当前系统备份成镜像（P235 / PDF 第244页）。

## 12. 常见坑速查

| # | 坑 | 现象 | 处理 | 出处 |
|---|---|---|---|---|
| 1 | 非闪迪 TF 卡 | 启动卡住 / `reboot` 失效 | 换 class10 闪迪卡 | P6 / PDF 15 |
| 2 | 电源不足或不稳 | 反复重启、启动卡住 | 换 5V/2A~3A 好电源+短线；**严禁 >5V** | P29 / PDF 38 |
| 3 | Micro HDMI 转接头太宽 | 和 Type-C 插不进同一个板 | 用窄头/软排线转接 | P7 / PDF 16 |
| 4 | 用 Etcher 烧 Android | 起不来 | Android 只能 Windows + PhoenixCard 4.2.8 | P22 / PDF 31 |
| 5 | 26pin SPI/I2C/UART 不通 | 没有 `/dev/spidev1.1`、`/dev/i2c-3`、`/dev/ttyS5` | `orangepi-config` 打开对应 dtbo 再重启 | P118–P126 / PDF 127–135 |
| 6 | 开 PWM3/4 后串口没了 | 调试串口无输出 | 这是复用，`disable-uart0` 的必然结果 | P127 / PDF 136 |
| 7 | debian12/ubuntu24.04 网卡名 | `ip a s eth0` 报错 | 改成 `end0` | P62 / PDF 71 |
| 8 | 改 `/etc/network/interfaces` | WiFi/静态 IP 异常 | 用 `nmcli`/`nmtui` | P63、P76 / PDF 72、85 |
| 9 | 老镜像自带 wiringOP 跑硬件 PWM | 不生效 | 用新版 wiringOP 源码重编（v1.0.2 镜像自带的不行） | P129 / PDF 138 |
| 10 | 以为 Linux 能硬解/GPU/TV-OUT | 功能缺失 | 适配就是 NO，需 Android 12 | P42 / PDF 51 |
| 11 | 以为 3 个 USB 都在板上 | 只找到 1 个 | 另 2 个要 13pin 扩展板 | P2 / PDF 11 |
