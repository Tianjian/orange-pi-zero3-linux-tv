## 1. 口径与数据来源

1. **引脚顺序/物理脚号**：26pin 按“左列奇数 1/3/…/25、右列偶数 2/4/…/26”，13pin 为单排 1–13。手册只写“顺序请参考开发板丝印图”，故 1 脚方位以板上方形焊盘/丝印为准，本文件按手册表格脚号叙述。
2. **复用功能**：以厂商 SDK 的 pinctrl 分组为准（`hardware/dts-ref/sun50i-h616.dtsi` + 官方 dtso），并用 Linux 主线 `pinctrl-sun50i-h616.c`（v6.15）的功能表补充每个引脚的函数名。**没有出现在这两处的功能一律不写**。
3. **PC/PI 口**：SDK DTS 里排针上的 PC5/6/7/8/9/10/11/14/15 只出现在 `mmc2_pins`（SDIO/eMMC）组，而 `&mmc2` 在 zero3.dts 中未启用、板上也无 eMMC/NAND；因此这些脚**实际就是纯 GPIO**（PC7/PC15 另有 `spi0` 功能，但 SPI0 已被板载 16MB NOR 占用 CS0，排针这两脚未被使用）。13pin 的 PC1 同理只在 `mmc2_pins` 组；PI6 的 `uart2`/`i2c0` 功能需要 PI5 配对，而 PI5 不在任何排针上。
4. **dtso 行为**：逐行读取 `hardware/dts-ref/overlay/*.dts`，见 6.3 节。
5. **wPi 号**：以手册 3.17 的 `gpio readall` 截图为权威（截图同时印出 GPIO/wPi/Name/Mode/V/Physical 六列），并与 wiringOP `pinToGpio_ZERO_2` 源码交叉核对。
6. **可复核性**：以上 DTS 结论同时对照了官方 SDK 6.1 分支 `arch/arm64/boot/dts/allwinner/sun50i-h618-orangepi-zero3.dts` 与 `sun50i-h616.dtsi`（已收录于 `hardware/dts-ref/`），可本地逐行复核。

**13pin 扩展板限制（手册 3.15）**：
- 插入扩展板后，13pin 的 10、11、12 脚（PC1/PI16/PI6）无法再使用；13 脚用于扩展板红外接收。
- 扩展板提供 2 个 USB 2.0 Host、耳机左右声道、TV-OUT、红外接收。
- 扩展板上的 **MIC 在 Orange Pi Zero 3 上无法使用**。
- 13pin 只有 1 个 5V 和 1 个 GND；同时接两个 USB 设备时供电脚不够，可从 26pin 的 5V/GND 借（手册 2.10 e）。13pin 两个 USB Host 的 VBUS 由 **PC16 使能**（zero3.dts `reg_usb1_vbus`）。

## 4. GPIO 编号规律与验算

### 4.1 规律

H618 的 GPIO 都在主 pinctrl（原理图 U1B）里，Linux 把它做成**一个 gpiochip**（通常 `gpiochip0`，基址 0；另有 r_pio/AXP 扩展时才出现其他 chip，用 `gpiodetect` 确认）。编号为：

```
line = (bank - 'A') * 32 + pin
bank: PA=0  PB=1  PC=2  PD=3  PE=4  PF=5  PG=6  PH=7  PI=8  PJ=9  PK=10  PL=11
```

示例：PH5 = 7×32+5 = **229**；PC9 = 2×32+9 = **73**；PI16 = 8×32+16 = **272**；PH10 = 7×32+10 = **234**。libgpiod 直接用这个 line 号，例如 `gpioset gpiochip0 229=1`（PH5）。

## 5. wiringOP 的 wPi 号

### 5.1 `gpio readall` 的口径（容易读错）

手册 3.17 原文“其中 1 到 26 号引脚与开发板上的 26 Pin 引脚是一一对应的”描述的是 readall 的 **Physical 列**（排针物理脚 1–26），**不是 wPi 列**。同一页截图可读出：

- 物理 7 脚那一行是 `73 | 2 | PC9 | OFF | 0 | 7`，即 **wPi 2 = PC9**；手册 3.18.1 也明写“7 号引脚—对应 GPIO 为 PC9—对应 wPi 序号为 2”，并用 `gpio mode 2 out` 演示。
- wPi 从 **0** 开始，且只分配给 GPIO；电源/GND 脚在 readall 中 wPi 列为空。
- 手册 3.17 的 b–e 条“27/29/31/33 号引脚对应 13pin 的 10/11/12/13 脚”说的是 **Physical 27/29/31/33**（readall 把 13pin 的 4 个 GPIO 排在虚拟 40 位排针的 27/29/31/33 行），它们的 wPi 是 **17/18/19/20**。
- 手册 3.17 的 f 条“28、30、32、34 号引脚为空”与 3.19“新版 readall 新增 28/30 表示 PWM3/PWM4”不矛盾：28/30 是 Physical 行，对应 **PH0/PH1**（调试串口 TX/RX 复用 PWM3/PWM4），不在 26pin/13pin 排针上；32/34 仍为空。

### 5.4 常见坑

- 用 `gpio mode 2 out` 控制的其实是 26pin **7 脚 PC9**，不是 3 脚、也不是物理 2 脚。
- 拿 wPi 号当物理脚号会差很多（如物理 11 脚是 wPi 5）。
- 13pin 的 4 个 GPIO 不是 wPi 27/29/31/33，而是 17/18/19/20。
- 电源/GND 脚没有 wPi，`gpio write` 不能给它们供电。

| `ph-i2c3` | `&i2c3` + `/aliases` | `pinctrl-0 = <&i2c3_ph_pins>`；`status = "okay"`；alias `i2c3` | PH4/PH5 = 26pin 5/3 → `/dev/i2c-3` |

## 7. 使用方式

### 7.1 libgpiod（推荐）

H618 的 gpio 线没有名称，`gpiofind` 用不上，直接用 line 号：

```bash
# 确认 chip 与行号（H618 主线通常为 gpiochip0，base 0）
gpiodetect
gpioinfo gpiochip0 | sed -n '220,240p'

# 输出：PH5 = line 229（26pin 3 脚）
gpioset gpiochip0 229=1        # libgpiod v1
gpioset -c gpiochip0 229=1     # libgpiod v2

# 输入 / 监视
gpioget gpiochip0 229
gpiomon gpiochip0 234          # PH10，13pin 13 脚 IR
```

注意：`gpioset` 退出后引脚状态是否保持取决于 libgpiod 版本/参数（v2 默认释放）；需要持续输出时用 `gpioset --mode=wait` 或 `-t 0` 之类参数，或写小程序/daemon。

### 7.2 wiringOP

```bash
sudo gpio readall                 # 查 wPi/Physical/GPIO/模式/电平
sudo gpio mode 2 out              # wPi 2 = PC9 = 26pin 7 脚
sudo gpio write 2 1
sudo gpio read 2
sudo gpio mode 2 in
sudo gpio mode 2 up               # 上拉（输入模式）
sudo gpio mode 2 down
sudo gpio serial /dev/ttyS5       # kernel 6.1；5.4 为 /dev/ttyAS5
```

26pin 上拉/下拉设置方法见手册 3.18.2；SPI/I2C/UART/PWM 需先用 `orangepi-config` 打开对应 overlay（见 6.3）。

### 7.3 PWM

```bash
# sysfs 方式（pwmchip0，通道 1–4 对应 PWM1–PWM4）
echo 1 > /sys/class/pwm/pwmchip0/export
echo 20000000 > /sys/class/pwm/pwmchip0/pwm1/period      # 20ms = 50Hz
echo 1000000  > /sys/class/pwm/pwmchip0/pwm1/duty_cycle  # 5%
echo 1        > /sys/class/pwm/pwmchip0/pwm1/enable

# wiringOP 硬件 PWM（v1.0.2 之后镜像；wPi 4 = PWM1）
gpio mode 4 pwm
gpio pwm 4 512        # CCR
gpio pwmr 4 2048      # ARR
gpio pwmc 4 5         # 分频 5
gpio pwmTone 4 20000  # 直接设频率
```

注意：PWM1/PH3 与 UART5_RX、PWM2/PH2 与 UART5_TX 冲突（手册 3.18.6）；PWM3/PWM4 与调试串口冲突，需 `disable-uart0`，关掉后调试串口不可用。

### 7.4 sysfs GPIO 已废弃

`/sys/class/gpio`（export/unexport）自 Linux 4.8 起标记为 deprecated，较新内核可能未编译 `CONFIG_GPIO_SYSFS` 或直接不提供；新代码请用 libgpiod（`/dev/gpiochipN`）或内核 GPIO 子系统。

### 7.5 overlay 对照

见 6.3 表格；`orangepi-config` → System → Hardware → 空格选中 → Save → Back → Reboot。

## 8. 设备树片段示例（sun50i-h618）

> **示例，节点名/分组名以 SDK 源码为准。** 厂商 `hardware/dts-ref/sun50i-h616.dtsi` 已提供 `uart5_ph_pins`、`i2c3_ph_pins`、`spi1_pins`、`spi1_cs1_pin`、`uart0_ph_pins`、`ir_rx_pin`、`pwm1_ph_pin`…`pwm4_ph_pin`，因此打开外设只需引用现成分组；**主线 v6.15 的 `sun50i-h616.dtsi` 没有 `uart5_ph_pins` 和 `spi1_cs1_pin`**，在纯主线内核上需要自行补分组（见示例后半段）。

```dts
/* 示例，节点名以 SDK 源码为准（厂商 6.1 DTS 可直接这样写） */
&uart5 {
	pinctrl-names = "default";
	pinctrl-0 = <&uart5_ph_pins>;	/* PH2=TX / PH3=RX，26pin 8/10 */
	status = "okay";
};

&i2c3 {
	pinctrl-names = "default";
	pinctrl-0 = <&i2c3_ph_pins>;	/* PH4=SCL / PH5=SDA，26pin 5/3；板上 2K 上拉 */
	status = "okay";
};

&spi1 {
	pinctrl-names = "default";
	pinctrl-0 = <&spi1_pins>, <&spi1_cs1_pin>;	/* PH6/7/8 + PH9，26pin 23/19/21/24 */
	status = "okay";

	spidev@1 {
		compatible = "rohm,dh2228fv";	/* 与官方 spi1-cs1-spidev.dts 一致 */
		reg = <1>;
		spi-max-frequency = <1000000>;
	};
};

/* 13pin 红外接收（默认已 okay，这里仅示意） */
&ir {
	pinctrl-names = "default";
	pinctrl-0 = <&ir_rx_pin>;	/* PH10 */
	status = "okay";
};
```

纯主线内核缺少的两个分组，可按下面补（分组标签名自取，避免与主线重名）：

```dts
&pio {
	uart5_ph_pins: uart5-ph-pins {
		pins = "PH2", "PH3";
		function = "uart5";
	};

	spi1_cs1_pin: spi1-cs1-pin {
		pins = "PH9";
		function = "spi1";
	};
};
```

要点：

1. H618 的 3.3V IO 域：`vcc-pc/ph/pi` 由 3.3V（AXP313A 的 DLDO1）供电，与手册“GPIO 3.3V”一致。
2. I2C3 上拉是板载 2K 到 3.3V，设备树一般不必再加 `bias-pull-up`；总线上并接设备后等效上拉会变小，注意总线电容/速率。
3. PH5 的 `SPI1_CS0` 与 I2C3 SDA 只能二选一；要用 I2C3 就必须用 CS1(PH9)，因此 `spidev1.1` 的 `reg = <1>`。
4. 同一组引脚不要同时 `okay`（如 `uart5` 与 `pwm1/pwm2`、`spi1` 与 `uart2`/`i2c4`）。

## 9. 电气与复用注意事项

1. **电平**：26pin 的 17 个 GPIO 全部 3.3V，不可直接接 5V 信号（是否 5V 容忍 ❓，按不容忍处理）。
2. **5V**：26pin 2/4 脚、13pin 1 脚为 VCC-5V，与 Type-C VBUS 同网络；手册说明可反过来用 5V 脚给整板供电（5V/2A 或 3A），且 5V 输出“插电即有、软件不可关断”。不要同时从 Type-C 和 5V 排针注入电源。
3. **3.3V**：26pin 1/17 脚为 VCC3V3-EXT；手册未给最大电流 ❓，不要当大功率电源用。
4. **I2C3**：PH4/PH5 板载 2K 上拉到 3.3V（R30/R31）；`/dev/i2c-3`；地址扫描 `i2cdetect -y 3`。
5. **SPI1**：只有 CS1（PH9，24 脚）；MOSI=19、MISO=21、CLK=23；测试时短接 19/21；`/dev/spidev1.1`；官方 spidev 默认 `spi-max-frequency = <1000000>`，手册示例 500kHz，实际上限 ❓。
6. **UART5**：8=TX、10=RX，3.3V TTL；`gpio serial /dev/ttyS5`（6.1）或 `/dev/ttyAS5`（5.4）。
7. **PC9（7 脚）**：原理图 P1 显示 PC9 经 R42 0Ω 接 AXP313 的 `PMU_IRQ`；作输出可能干扰 PMIC 中断，建议只作输入或避免使用。
8. **PC5/PC6 启动脚**：PC5（13 脚）10K 下拉（R19）、PC6（11 脚）10K 上拉（R20），对应 `BOOT_SEL3/BOOT_SEL4`；上电瞬间电平被采样，外接电路不要强拉反电平，否则可能改变启动模式。启动完成后可当 GPIO 用。
9. **PC14/PC15**：26pin 16/18 脚网络名为 `GPIO-SDA`/`GPIO-SCK`，各 2K 上拉到 3.3V；H618 复用表里没有对应 TWI 功能，若要 I2C 只能用 GPIO 模拟。
10. **13pin 扩展板**：插上后 10/11/12 脚不可用，13 脚给红外；MIC 不可用；USB Host 的 VBUS 由 PC16 使能，需要 5V/GND，13pin 只有一组，两个 USB 设备时从 26pin 借电。
11. **USB**：13pin 3–6 脚是 SoC USB PHY 差分线（90Ω），不能当 GPIO，也不自带 VBUS。
12. **音频/TV-OUT**：7/8/9 脚是模拟信号，不是数字 GPIO。

## 10. 差异与待确认

| 编号 | 内容 | 说明 / 处理 |
|---|---|---|
| D1 | 手册 3.17“1–26 号引脚与 26pin 一一对应”易被误读成 wPi 1–26 = 物理脚 | 该句指 readall 的 **Physical** 列；wPi 是 0 起始且只给 GPIO（PC9=wPi 2 为证）。**不要按 wPi=物理脚 写代码**，一律以 `gpio readall` 为准 |
| D2 | 手册 3.17 说“28、30、32、34 号为空”，3.19 说新版 readall“新增 28 和 30 表示 PWM3/PWM4” | 是 readall 版本差异；28/30 是 **Physical 行**（PH0/PH1，调试串口 TX/RX），不在 26pin/13pin 排针上；32/34 仍为空 |
| D3 | 13pin 的 wPi 不是 27/29/31/33 | 27/29/31/33 是 Physical 行；wPi 为 17/18/19/20（PC1/PI16/PI6/PH10） |
| D4 | 手册 3.16 只写 pin16=PC15、pin18=PC14；原理图网络名为 `GPIO-SDA`（PC15）与 `GPIO-SCK`（PC14），各带 2K 上拉 | 说明这两脚被设计成“类 I2C”用途，但复用表无对应 TWI；写代码仍用 PC15/PC14（79/78） |
| D5 | 26pin 连接器符号内 pin24=`SPI-CE0`、pin26=`SPI-CE1`，与 SoC 实际不符 | pin24 网络是 `SPI1_CS`，SoC 为 PH9 = **SPI1_CS1**（readall 名 `CE.1`，`/dev/spidev1.1`）；pin26 是 PC10 普通 GPIO。符号名是连接器器件引脚名，不能当功能名 |
| D6 | 手册未提 PC9 兼作 PMU_IRQ | 原理图 P1：PC9 —R42 0Ω— AXP313 `PMU_IRQ`；作输出前请评估对 PMIC 中断的影响 |
| D7 | 手册 3.15 同时说 13pin 10/11/12 扩展板时不可用、13 脚给红外，但 3.15 表格仍列 PC1/PI16/PI6 | 表格是“不接扩展板时的 GPIO 能力”；接扩展板后以扩展板功能为准 |
| D8 | **PI16 在 `ext_rgmii_pins` 组内**，而 `&emac0` 默认 okay | 该组包含 `"PI16"` 且 function=`emac0`（驱动注释 EPHY_CLK）。因此 Ethernet 启用时 PI16 会被 pinctrl 占用（readall 显示 ALT2 与此吻合），13pin 11 脚作 GPIO 可能被拒（EBUSY）。手册仍标 GPIO 272；实际使用前请实测，必要时从 `ext_rgmii_pins` 移除 PI16 或关 emac0（会失去千兆网） |
| D9 | 原理图引脚名串与主线 pinctrl 驱动功能表不完全一致 | 原理图另标 PH0/PH1 的 CAN_TX/CAN_RX、PH3 的 SPDIF_IN，主线 v6.15 驱动未实现；vendor 6.1 内核是否支持 ❓ |
| D10 | `disable-uart0` | 手册 3.18.6 提到该 overlay，但 `hardware/dts-ref/overlay/` 目录中未包含对应 dtso（可能在 SDK 其它路径）；以 SDK 实际文件为准 |
| D11 | 未确认项 | H618 datasheet 未随资料提供，无法确认：① PI16 作 GPIO 的实测可行性（D8）；② I2C3 支持速率；③ 3.3V 输出电流上限；④ SPI1 上限频率；⑤ GPIO 是否 5V 容忍（按不容忍处理） |
| D12 | CSV 中电源/GND 的 `gpio_line`/`wpi` 为空 | 有意为之：这些脚没有 GPIO 号；不要用空值去拼 `gpioset` 命令。若内核把 gpiochip 基址设为非 0，line 号会整体偏移，以运行时 `gpiodetect`/`gpioinfo` 为准 |
