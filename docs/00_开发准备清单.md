# 00 开发准备清单（可执行版）

> 这份清单回答一个问题：**拿到 Orange Pi Zero 3，要把它变成一台能干活的目标板，按什么顺序准备、每步怎么验收。**
> 所有结论来自用户手册 v1.6 与原理图 Rev 1.2 的交叉核对，页码/图页标注在括号里；
> 详细依据见 [01](01_硬件规格与系统.md)、[02](02_原理图分析.md)、[03](03_引脚定义与复用.md)。

---

## A. 先确认你手里的板子

| 要确认的 | 怎么看 | 影响 |
|---|---|---|
| 内存版本 | 板面丝印 / 购买记录（1/1.5/2/4GB） | 决定能否跑桌面、Docker、大模型推理 |
| Wi-Fi 模块 | 看 U60 丝印；或用 `cat /sys/bus/sdio/devices/*/device` + `dmesg \| grep -i wifi` | `20U5622` 是 CdTech **模块**型号，die = `AW859A` = `UWE5622`（同一颗芯片、同一套驱动），已结案 |
| 板卡版本 | 丝印 `ORANGEPI Zero3-4G` + 版本号 | 原理图对应 Rev 1.2，2023-07-13 |
| 是否带 13pin 扩展板 | 看包装 | 不带就没有第二个 USB、音频、TV-OUT、IR |

> **重要**：Wi-Fi/BT 只有厂商内核树自带驱动（6.1 树内 `drivers/net/wireless/uwe5622/`，编成
> `uwe5622_bsp_sdio`/`sprdwl_ng`/`sprdbt_tty` 三个模块）。主线内核没有该驱动，也没有排队中的上游补丁；
> 走主线要么移植（Armbian 有 DKMS 版），要么用 USB WiFi。

## C. 主机环境准备（两条路线）

### C1. 应用/驱动开发（本仓库路线，当前主机即可）

```bash
./scripts/setup_toolchain.sh --with-tools   # Arm GNU 11.2 aarch64 工具链 + dtc + qemu
source scripts/env.sh
make -C examples check                      # 交叉编译 + 本机 -Werror + PTY 测试
./scripts/check_env.sh                      # 环境体检
```

验收标准：

- `aarch64-none-linux-gnu-gcc --version` 有输出
- `file build/aarch64/gpio_blink` 显示 `ELF 64-bit LSB ..., ARM aarch64`
- `make -C examples check` 全部 PASS

### C2. 完整镜像开发（需要 Ubuntu 22.04 x64）

`orangepi-build` **只支持 Ubuntu 22.04 x64**，禁止 WSL、禁止在板上编（手册 P243）。建议用虚拟机/独立机器：

```bash
sudo apt install -y git build-essential
git clone https://github.com/orangepi-xunlong/orangepi-build.git -b next
cd orangepi-build
sudo ./build.sh          # 菜单式：U-Boot / Kernel / Rootfs / Image
```

- 磁盘 ≥60GB，内存 ≥8GB（经验值，手册未写）。
- 改内核/U-Boot 源码前：在 `userpatches/config-default.conf` 加 `IGNORE_UPDATES="yes"`，否则会被同步覆盖（P250）。
- 详细步骤与产物路径见 [04_orangepi-build_SDK.md](04_orangepi-build_SDK.md)。

验收标准：`orangepi-build/output/images/.../*.img` 生成，且能烧卡启动。

## D. 上板前检查（5 分钟，避免烧板）

- [ ] 万用表量 Type-C 电源空载输出：**5.0–5.2V**，极性正确
- [ ] 检查板子 26pin/13pin 无短路、无异物
- [ ] USB-TTL 电平跳线选 **3.3V**（很多模块默认 5V！）
- [ ] 串口接线：模块 TXD→板 RX，RXD→板 TX，GND↔GND，**不接 VCC**
- [ ] TF 卡已烧录并 `sync`，插入到位
- [ ] 先接串口再上电，避免错过 U-Boot 日志

## E. 首次启动验收

| # | 检查 | 命令/观察 | 通过标准 |
|---|---|---|---|
| E1 | 串口有输出 | `picocom -b 115200 /dev/ttyUSB0` | 看到 U-Boot + 内核日志 |
| E2 | 能登录 | `root` / `orangepi` | 进入 shell |
| E3 | 板型正确 | `tr -d '\0' < /proc/device-tree/model` | 含 `OrangePi Zero3` |
| E4 | 内存符合 | `free -h` | 与购买版本一致（约 1/1.5/2/4GB 减去预留） |
| E5 | 存储扩容 | `df -h /` | 首次启动自动扩到整卡（P49） |
| E6 | 温度正常 | `cat /sys/class/thermal/thermal_zone0/temp` | 待机 40–60°C |
| E7 | chipid 可读 | `grep chipid /sys/class/sunxi_info/sys_info` | 有一串唯一 ID |
| E8 | 网口 | `ip -br addr` | eth0 有 IP |
| E9 | SSH | 主机 `ssh orangepi@<IP>` | 能登录 |
| E10 | 一键体检 | `bash scripts/onboard_selftest.sh` | 报告无异常项 |

## F. 外设功能验收矩阵

先 `sudo orangepi-config` → System → Hardware 打开需要的复用，再逐项验收。硬件细节见 [03](03_引脚定义与复用.md)。

| 功能 | 使能项 | 接线 | 验收命令 | 期望 |
|---|---|---|---|---|
| GPIO 输出 | 无需 | LED+330Ω 到 3.3V，PC7(22 脚) | `sudo ./gpio_blink -l 71 -n 10` | LED 闪烁 |
| GPIO 输入/中断 | 无需 | PC6(11 脚)—按键—GND + 10K 上拉 | `sudo ./gpio_event -l 70 -b pull-up` | 打印边沿事件 |
| UART5 | `ph-uart5` | 8↔10 脚短接 | `sudo ./uart -d /dev/ttyS5` | `PASS` |
| I2C3 | `ph-i2c3` | SDA=3、SCL=5、3.3V、GND | `sudo ./i2c_scan -d /dev/i2c-3` | 扫到设备 |
| SPI1 | `spi1-cs1-spidev` | 19↔21 脚短接 | `sudo ./spi_loopback -d /dev/spidev1.1` | `PASS` |
| PWM1/2 | `ph-pwm12`（取消 ph-uart5） | 10 脚(PH3)=PWM1 / 8 脚(PH2)=PWM2 | `sudo ./pwm -c 1 -f 50 -d 50 -t 5` | 示波器见 50Hz |
| 以太网 | 默认开 | 网线 | `iperf3` 对测 | 接近千兆线速 |
| Wi-Fi | 默认（厂商驱动） | — | `nmcli dev wifi connect` | 能上网 |
| 蓝牙 | 默认 | — | `bluetoothctl` scan | 能发现设备 |
| HDMI | 默认开 | Micro HDMI | 接显示器 | 有画面（GPU 3D 在 Linux 下不可用） |
| USB Host | 默认 | USB 键鼠/U 盘 | `lsusb`、`lsblk` | 识别 |
| 音频 | `codec` 默认 | 13pin 扩展板 3.5mm | `aplay test.wav` | 有声音 |
| IR | `ir` 默认 | 13pin 扩展板 + 遥控器 | `ir-keytable` / `evtest` | 收到键值 |
| 看门狗 | 默认 | — | `sudo watchdog_test 10` | 不喂狗会重启 |
| SPI Flash | 默认 | — | `cat /proc/mtd` | 看到 SPI NOR 分区（器件 16Mbit=2MB） |

> 没有硬件时：`make test` 用 PTY 验证 UART 逻辑、`file` 验证 aarch64 产物、`dtc` 验证 overlay 语法；
> 其余项必须上板，别把“编译通过”当成“功能验证”。

## G. 软件工程准备

- [x] 仓库结构：`docs/`（分析）+ `hardware/`（引脚/数据）+ `examples/`（可运行）+ `scripts/`（工具）+ `dts/`（overlay）

- [x] 构建入口：`make` / `make check` / `make verify`
- [x] 部署：`scripts/deploy.sh`（scp + ssh 运行）
- [x] 板端体检：`scripts/onboard_selftest.sh`
- [x] 镜像烧写：`scripts/flash_image.sh`（拒绝系统盘、可校验）
- [ ] 你的产品代码：按 `examples/` 骨架复制，保持“无第三方依赖、5.4/6.1 双内核兼容”
- [ ] CI：把 `make check` 接入（不需要板子），上板测试单独流水线
- [ ] 版本管理：固件版本 + 设备树版本 + 内核版本 三者绑定记录

## H. 风险清单（按影响排序）

| 风险 | 影响 | 规避 |
|---|---|---|
| 电源不合规（>5V、劣质线） | **烧板** | 只用 5V 优质电源；上电前万用表量 |
| 26pin/13pin 的 5V 直连 Type-C VBUS（原理图 Sheet 4/5） | 反灌/倒灌，可能损坏主机 USB 口 | 不要同时从 Type-C 和排针供电；外设大电流用独立供电 |
| GPIO 全是 **3.3V** 电平（手册 P113） | 接 5V 传感器会烧 SoC | 5V 器件必须电平转换 |
| 非闪迪 TF 卡 | 启动卡死、reboot 异常 | 用闪迪 Class10 |
| Wi-Fi 只有厂商驱动（主线无） | 换主线内核后无 Wi-Fi | 用厂商 6.1 树，或移植 Armbian 的 uwe5622 DKMS，或用 USB WiFi |
| Linux 下 GPU/视频硬解/TV-OUT 不可用（P41） | 不能做播放器/3D | 用 Android 12，或只做 CPU 业务 |
| 26pin UART5 与 PWM1/2 冲突 | 打开 PWM 后串口模块失效 | 二选一，做资源规划表 |
| 13pin 11 脚 PI16 与以太网 emac0 pinctrl 重叠 | 作 GPIO 可能 EBUSY | 需要时裁剪 `ext_rgmii_pins` 中的 PI16 并复测以太网 |
| 无 eMMC、无 NVMe | 存储只有 TF + 2MB SPI NOR | 选高耐用 TF 卡；启用 overlayroot 防掉电损坏 |
| 无 RTC 电池（原理图 Sheet 4 仅 VCC-RTC 电容） | 断电时间不保持 | 联网 NTP，或外接 RTC 模块 |
| 散热不足 | 80°C+ 降频 | 散热片/风扇，机箱留风道 |
