# 05 快速上手：从开箱到第一个点灯

> 目标：按本文顺序做完，你会在 1–2 小时内得到一台可串口登录、可 SSH、可编译运行自写 ARM64 程序、
> 并验证过 GPIO/UART/I2C/SPI/PWM 的 Orange Pi Zero 3 开发环境。
>
> 适用镜像：Orange Pi 官方 Debian 12 / Ubuntu 22.04 / Ubuntu 24.04（内核 6.1），Debian 11 / Ubuntu 20.04（内核 5.4）。
> 页面级依据见 [01_硬件规格与系统.md](01_硬件规格与系统.md)，引脚细节见 [03_引脚定义与复用.md](03_引脚定义与复用.md)。

---

## 0. 配件清单（缺一不可的先备齐）

| 配件 | 要求 | 说明 |
|---|---|---|
| TF 卡 | ≥8GB，Class10，**建议闪迪** | 官方明确提示非闪迪卡有启动卡死/reboot 异常（手册 P6） |
| 电源 | 5V/2A 或 5V/3A，USB Type-C | 板子无独立 DC 口；手机快充头不一定兼容，优先用 5V 固定输出 |
| Micro HDMI 线 | 普通细头 | 宽转接头会和 Type-C 电源口干涉（手册 P7） |
| USB-TTL 串口模块 | **3.3V 电平**，CH340/CP2102/FT232 | 调试串口是 3.3V TTL，不是 RS232；不要接模块的 5V |
| 杜邦线 | 母-母若干 | 26pin 是 2.54mm 排针 |
| 13pin 扩展板 | 可选 | 提供 2×USB、音频、TV-OUT、IR；注意 MIC 不支持 |

> 只做纯 Linux 开发可以不要 HDMI 显示器：串口 + SSH 足够。

## 1. 烧写系统镜像

1. 到资料下载页下载镜像：
   中文 <http://www.orangepi.cn/html/hardWare/computerAndMicrocontrollers/service-and-support/Orange-Pi-Zero-3.html>
   （手册 P11）。选择 `OrangePi_Zero3_*.img.xz`，桌面版带 Xfce，服务器版无桌面。
2. Linux 主机烧写（推荐，安全校验最全）：

   ```bash
   lsblk                                   # 找到 TF 卡，例 /dev/sdb（不要选 /dev/sdb1）
   ./scripts/flash_image.sh ~/Downloads/OrangePi_Zero3_*.img.xz /dev/sdb --verify
   ```

   Windows 用 balenaEtcher（手册 P12），Ubuntu 图形界面也可用 `Startup Disk Creator` 之外的 dd 方式（手册 P18）。
3. 烧完 `sync` 再拔卡。第一次启动会自动扩容 rootfs（手册 P49），**不要**在首次启动中断电。

> 板载 SPI NOR Flash（U61 ZB25VQ16 = 16Mbit/2MB；手册 P2 写“16MB”）出厂带一个微型 Linux：
> 不插 TF 卡上电红灯亮、绿灯闪是正常现象（手册 P46），
> 不是故障。它不影响 TF 卡启动优先级（TF 卡优先）。

## 2. 调试串口接线（强烈建议第一步就接）

板上 DEBUG 是 3 针 2.54 排针（原理图 Sheet 5），UART0，**3.3V TTL、115200 8N1**：

```
USB-TTL 模块             Orange Pi Zero 3
  TXD  ────────────────►  DEBUG 第2脚 (UART0-RX / CPUX-URX)
  RXD  ◄────────────────  DEBUG 第3脚 (UART0-TX / CPUX-UTX)
  GND  ────────────────  DEBUG 第1脚 (GND)
  (不要接 3V3/5V)
```

```bash
./scripts/serial_console.sh --list      # 确认 /dev/ttyUSB0 在
./scripts/serial_console.sh /dev/ttyUSB0
# 或：picocom -b 115200 /dev/ttyUSB0
```

上电后应看到 U-Boot 和内核日志，登录账号（手册 P43）：

| 账号 | 密码 |
|---|---|
| `root` | `orangepi` |
| `orangepi` | `orangepi` |

> 串口无输出排查顺序：TX/RX 是否交叉 → 模块电平是否 3.3V → 板子是否真的上电（红灯）→
> 波特率 115200 → 换一根线。串口有输出但登录不了，先用 `root/orangepi`。

## 3. 首次启动自检

把本仓库的 [onboard_selftest.sh](../scripts/onboard_selftest.sh) 传到板子（或直接在板子上 `git clone` 本仓库）：

```bash
scp scripts/onboard_selftest.sh orangepi@<板子IP>:~/
ssh orangepi@<板子IP> 'bash ~/onboard_selftest.sh --full'
```

重点看：

- `model` 应为 `OrangePi Zero3`（或含 H618 的字符串）
- `chipid` 每个芯片唯一，可用于区分多块板
- 温度：待机 40–55°C 正常，>80°C 要加散热片
- `i2c/spi/pwm` 节点默认**没有**，这是正常的，需要第 6 步手动打开

## 4. 联网与 SSH

### 有线（最稳）

板载千兆网口，插上路由器 DHCP 即可：

```bash
ip -br addr                 # 看 eth0 拿到的 IP
ssh orangepi@<IP>
```

### WiFi（命令行，服务器版）

```bash
sudo nmcli dev wifi list
sudo nmcli dev wifi connect "<SSID>" password "<密码>"
# 或交互式：sudo orangepi-config → Network → WiFi
```

### 无线热点（把板子当 AP）

手册 P70 用 `create_ap`；桌面版也可用 NetworkManager 热点。做 IoT 网关时很实用。

### 固定 IP（可选）

```bash
sudo nmcli con mod "<连接名>" ipv4.method manual ipv4.addresses 192.168.1.50/24 ipv4.gateway 192.168.1.1
sudo nmcli con up "<连接名>"
```

### SSH 免密

```bash
ssh-keygen -t ed25519            # 主机上，已有则跳过
ssh-copy-id orangepi@<IP>
```

## 6. 打开 26pin 外设（UART5 / I2C3 / SPI1 / PWM）

**官方镜像默认全部关闭**，必须显式开启（手册 P116–P128）：

```bash
sudo orangepi-config
#  System → Hardware
#    [ ] ph-uart5              -> 26pin 8/10 脚 UART5
#    [ ] ph-i2c3               -> 26pin 3/5 脚 I2C3
#    [ ] spi1-cs1-spidev       -> 26pin SPI1，生成 /dev/spidev1.1
#    [ ] ph-pwm12              -> 26pin 8/10 脚 PWM1/PWM2（与 UART5 冲突！）
#  保存 → Back → Reboot
```

冲突关系（这是本板最容易踩的坑）：

| 引脚 | 功能 A | 功能 B | 结论 |
|---|---|---|---|
| PH2 / PH3（8/10 脚） | UART5 TX/RX | PWM2 / PWM1 | **二选一** |
| PH0 / PH1（DEBUG） | UART0 调试串口 | PWM3 / PWM4 | 选 PWM 就没有串口控制台 |
| PH4 / PH5（3/5 脚） | I2C3 | — | 可与 UART5 同时用 |
| PH6–PH9（19/21/23/24 脚） | SPI1 | — | 独立 |

重启后确认节点：

```bash
ls /dev/ttyS5 /dev/i2c-3 /dev/spidev1.1 /sys/class/pwm/pwmchip0
```

> 5.4 内核的 UART5 节点是 `/dev/ttyAS5`，别照抄 6.1 的命令。

## 7. 第一个程序：点灯

26pin 第 22 脚是 **PC7 = GPIO 71**：纯 GPIO、无启动 strap、无其他电路占用，适合入门。

> ⚠️ 不要用第 7 脚 PC9（GPIO 73）点灯：原理图上它经 0Ω 电阻接 AXP313A 的 **PMU_IRQ**
> （Sheet 1），当输出用会干扰电源管理中断。第 11 脚 PC6/第 13 脚 PC5 是 BOOT_SEL 启动脚，
> 上电瞬间电平参与启动模式选择，做输出也要谨慎。

### 7.1 接线

```
3.3V (1 脚或 17 脚) ── 330Ω ── LED 阳极 ──►│── LED 阴极 ── PC7 (22 脚)
```

输出低电平时点亮（灌电流，推荐）；接反则输出高电平点亮。

### 7.2 三种点法

**A. wiringOP 命令行（官方镜像预装）**

```bash
gpio readall                 # 确认 PC7 对应 wPi 13
gpio mode 13 out
gpio write 13 1              # 灭
gpio write 13 0              # 亮
```

**B. 本仓库 C 程序（推荐，可移植、可交叉编译）**

```bash
# 主机上
make -C examples
./scripts/deploy.sh orangepi@<IP> build/aarch64/gpio_blink -l 71 -p 300 -n 20
# 或板子上
sudo ./gpio_blink -l 71 -p 300 -n 20
```

**C. sysfs（老教程常见，已废弃但 6.1 仍可用）**

```bash
echo 71 > /sys/class/gpio/export
echo out > /sys/class/gpio/gpio71/direction
echo 0 > /sys/class/gpio/gpio71/value
```

> 板载 LED 也可以直接点：`green_led` 对应 PC13，`red_led` 对应 PC12（手册 P46）：
> `echo default-on | sudo tee /sys/class/leds/green_led/trigger`

## 8. 跑通六个板级示例

| 示例 | 接线 | 命令 | 期望 |
|---|---|---|---|
| GPIO 输出 | LED + 330Ω 到 3.3V，PC7(22 脚) | `sudo ./gpio_blink -l 71 -p 300 -n 20` | LED 闪 20 次 |
| GPIO 事件 | PC6(11 脚)—按键—GND，10K 上拉到 3.3V | `sudo ./gpio_event -l 70 -b pull-up -n 5` | 每次按下打印 RISING/FALLING |
| UART5 回环 | 8 脚 TX ↔ 10 脚 RX 短接 | `sudo ./uart -d /dev/ttyS5` | `PASS: 回环数据完全一致` |
| I2C3 扫描 | SDA=3 脚、SCL=5 脚、3.3V、GND 接传感器 | `sudo ./i2c_scan -d /dev/i2c-3` | 打印设备地址网格 |
| SPI1 回环 | 19 脚 MOSI ↔ 21 脚 MISO 短接 | `sudo ./spi_loopback -d /dev/spidev1.1` | `PASS: 32 字节回环一致` |
| PWM | 示波器/LED 接 10 脚(PH3)=PWM1 或 8 脚(PH2)=PWM2 | `sudo ./pwm -c 1 -f 50 -d 50 -t 5` | 50Hz 方波，占空比可调 |

> 每个程序 `--help` 都有中文参数说明；`gpio_blink --info` 可查引脚当前电平。
> 没有硬件时，主机上 `make test` 会用 PTY 验证 UART 收发逻辑、用 `file` 验证 aarch64 产物。

## 9. 交叉编译工作流

```bash
./scripts/setup_toolchain.sh        # 一次性：Arm GNU 11.2 aarch64 工具链
source scripts/env.sh               # 可选，直接 make 也行
make -C examples                    # build/aarch64/
file build/aarch64/gpio_blink       # ELF 64-bit LSB, ARM aarch64
./scripts/deploy.sh orangepi@<IP> --sync
```

写自己的程序时，复制 `examples/*/` 的骨架即可：只用 glibc + Linux UAPI，不依赖 wiringOP/libgpiod，
在 5.4 和 6.1 内核上都能跑。

**在板子上直接编译**（镜像自带 gcc，适合快速迭代）：

```bash
make -C examples CC=gcc BUILD=./build-board
```

## 10. 进阶：内核 / 设备树 / SDK

- 完整镜像（U-Boot + 内核 + rootfs + 打包）编译：见 [04_orangepi-build_SDK.md](04_orangepi-build_SDK.md)，
  只能在 **Ubuntu 22.04 x64** 上跑，需要 ≥60GB 磁盘。
- 只想改设备树：SDK 里 `kernel/arch/arm64/boot/dts/sunxi/`，或写 overlay（模板见 `dts/`）。
- 验证引脚复用是否生效：`sudo cat /sys/kernel/debug/pinctrl/*/pinmux-pins | grep -E "PH2|PH3"`。
- 内核头文件：`sudo apt install linux-headers-$(uname -r)`（手册 P216），之后可编译 out-of-tree 驱动。

## 11. 常见问题（本板高频）

| 现象 | 原因 | 处理 |
|---|---|---|
| 不插卡的板子红灯亮绿灯闪 | SPI Flash 里的微型 Linux 在跑 | 正常，TF 卡优先启动 |
| TF 卡启动卡死 / `reboot` 失效 | 非闪迪卡兼容性 | 换闪迪 Class10 卡（手册 P6） |
| 串口乱码 | 波特率/电平不对 | 115200 8N1，3.3V TTL，TX/RX 交叉 |
| 串口完全无输出 | 只接了 USB 供电没接数据，或板子没启动 | 先确认红灯；换线；测 DEBUG 3 脚电压 |
| `Permission denied` 打开 gpiochip | 非 root / 不在 gpio 组 | `sudo`，或加 udev 规则（本仓库示例用 root 运行） |
| `Device or resource busy` | 引脚已被 LED/驱动/其他进程占用 | `gpioinfo`/`gpio readall` 查占用者，换引脚 |
| I2C 扫不到设备 | i2c3 没开 / 接线错 / 设备没供电 | `orangepi-config` 开 ph-i2c3；确认 3.3V 与 GND |
| SPI 收全 0 | MOSI/MISO 没短接，或 spidev1.1 不存在 | 短接 19/21；确认选了 spi1-cs1-spidev |
| PWM 无输出 | 与 UART5 冲突 | 取消 ph-uart5 再选 ph-pwm12，重启 |
| HDMI 黑屏 | 分辨率/线材 | 换细头 Micro HDMI 线；`orangepi-config` 改分辨率 |
| WiFi 连不上 5GHz | 模块/地区限制 | 先用 2.4GHz 验证；`nmcli dev wifi list` 看是否可见 |
| 温度 >80°C 降频 | 无散热 | 加散热片/风扇；`cat /sys/class/thermal/thermal_zone0/temp` |

## 12. 下一步建议

1. **固化环境**：把 `onboard_selftest.sh` 输出存档，作为“基线”。
2. **接口选型**：需要高速外设走 USB/以太网，需要实时性走 SPI/UART，别用 GPIO 软件模拟高速时序。
3. **供电**：26pin 的 5V 直连 Type-C VBUS，外接大功率 USB 设备时用带供电的 Hub，别从板子取大电流。
4. **量产**：SPI Flash 可存 U-Boot/小系统；量产用 `orangepi-build` 出定制镜像 + 首次启动脚本。
5. **可靠性**：长期运行开 `overlayroot`（手册 P236）或把 rootfs 挂只读，防突然断电损坏文件系统。
